# What's New in PostSharp 2027.0

The highlights of PostSharp 2027.0 are:

* **Faster builds of .NET projects.** With `dotnet build`, PostSharp compiles .NET projects in a background build server that keeps the compiler loaded between builds, on Windows, Linux and macOS. Each compilation is several times faster. Until now, only .NET Framework projects benefited from such a server. See [Background build server for .NET](#background-build-server-for-net).
* **Faster aspects at run time.** With advice parameter binding, now a public feature, advices receive typed parameters instead of an object allocated on each call, so the woven code computes only the values that the advices need and allocates no object for them. See [Advice parameter binding](#advice-parameter-binding).
* **Dependency injection in aspects.** An aspect can receive a service from dependency injection: the target class gets the service from its constructors, and the advices read it. The caching aspects are the first to use it, so each container can have its own cache. See [Dependency injection in aspects](#dependency-injection-in-aspects).
* **Support for .NET 11 and C# 15.** PostSharp supports the .NET 11 SDK, C# 15 and runtime async. See [Support for .NET 11 and C# 15](#support-for-net-11-and-c-15).
* **Cross-platform options interface and command line tool.** A browser-based user interface and the `postsharp` command line tool replace the Windows options application. See [Cross-platform options interface and command line tool](#cross-platform-options-interface-and-command-line-tool).
* **More than 100 bug fixes.** PostSharp 2027.0 fixes more than 100 bugs in the compiler, the aspect framework and the Pattern Libraries. Many of them come from the deep backlog, and about a third were found by AI agents. See [Bug fixes](#bug-fixes).

> [!NOTE]
> This release includes several breaking changes. Refer to <xref:breaking-changes-20270> for more detailed information.

## Background build server for .NET

Until PostSharp 2026.0, only .NET Framework projects could use the pipe server, a background process that keeps the compiler loaded between builds. Each compilation of a .NET project started a process of its own, which loaded and compiled the PostSharp compiler again.

PostSharp 2027.0 adds a pipe server for .NET. When you build with the .NET SDK (`dotnet build`), the compilations of your .NET and .NET Standard projects run in one background process, on Windows, Linux and macOS. The compiler stays loaded and compiled between projects and between builds, and the Pattern Libraries of the same version as PostSharp are loaded once. Each compilation loads the assemblies of the project into an assembly load context of its own, which is unloaded when the compilation ends, so the compilations do not affect each other. In our measurements on small projects, a compilation took about 0.25 seconds with a running server instead of about 1 second in a process of its own.

* The server is used by default. Set the `PostSharpUsePipeServer` MSBuild property to `False` to compile each project in a process of its own, as before.
* The MSBuild of Visual Studio still compiles .NET projects in a process of their own. A compilation for x86 never uses a pipe server, because a 32-bit process does not have enough address space for a server.
* The server exits after 15 minutes without a build. `postsharp shutdown` stops it at once.
* The server reads the assemblies of your projects into memory, so it does not lock their files.

To compile each project in a process of its own, for instance on a build agent, set the property in the project or in a `Directory.Build.props` file:

```xml
<PropertyGroup>
  <PostSharpUsePipeServer>False</PostSharpUsePipeServer>
</PropertyGroup>
```

Build-time code that keeps a reference to a type of the project in a static field of a shared library keeps the whole compilation in memory, and shares its state with the other projects that the server compiles. The new <xref:PostSharp.Extensibility.ProjectLocal`1> class stores build-time state per project instead. See <xref:in-process-memory-leaks> to detect and diagnose such leaks, including the `PostSharpVerifyLoadContextUnload` property, which makes the build fail when a compilation stays in memory.

## Advice parameter binding

Until now, the advices of an aspect received their context through an <xref:PostSharp.Aspects.AdviceArgs> object, such as <xref:PostSharp.Aspects.MethodExecutionArgs>. This object is allocated on the heap on each call, and it gives access to the arguments and the return value as <xref:System.Object> values, which the aspect must cast.

With advice parameter binding, an advice method declares the values it needs as typed parameters. A custom attribute on each parameter selects the value: an argument, the instance, the return value, the exception, a variable shared between advices, the reflection object of the target, and so on. The woven code computes only these values and allocates no object.

The Pattern Libraries already used this mechanism internally. PostSharp 2027.0 makes it public, with the following improvements:

* PostSharp checks the bound parameters against each target at build time. An advice that does not fit a target causes an error with a message code, instead of a compiler crash or invalid code.
* New bindings give an advice the exception (`[Exception]`), the return value in the method boundary advices (`[ReturnValue]`), and the reflection object of the target (`[Declaration]`).
* Advice methods can be generic. PostSharp infers the type arguments for each target, so values of value types are not boxed.
* `[CurrentTask]` gives the task that the caller of an async method observes, also for methods that return `ValueTask`.
* <xref:PostSharp.Aspects.Advices.OnMethodInvokeAsyncAdvice> accepts the `[Declaration]`, `[DeclarationName]`, `[DeclarationIdentifier]`, `[Arguments]`, `[Argument]` and `[Binding]` parameters, also in a generic advice method, and can return a `Task<T>` whose result becomes the result of the target method.
* Advices are grouped without a master advice. PostSharp infers the groups of each class: an advice joins the group of its class that has no advice of its kind yet. The new <xref:PostSharp.Aspects.Advices.GroupingAdvice.Group> property selects a group by name when the inference is ambiguous, also across the classes of an aspect, and the pointcut and the properties of a group can be set on any of its advices. See <xref:pointcuts>.
* `[SelfPointcut]` and the <xref:PostSharp.Aspects.Advices.GroupingAdvice.Master> property are obsolete. A group without pointcut applies to the target of the aspect, so `[SelfPointcut]` is redundant; set <xref:PostSharp.Aspects.Advices.GroupingAdvice.Group> instead of <xref:PostSharp.Aspects.Advices.GroupingAdvice.Master>. This is a breaking change: several advices of different kinds that each had `[SelfPointcut]` were separate groups, and are now one group, which shares <xref:PostSharp.Aspects.MethodExecutionArgs> and its <xref:PostSharp.Aspects.MethodExecutionArgs.MethodExecutionTag>. See <xref:breaking-changes-20270>.

The documentation of composite aspects has been reorganized around this feature. See <xref:member-level-aspects>, <xref:advice-parameter-binding> and <xref:complex-aspects>. To convert an existing aspect, see <xref:modernizing-aspects>.

## Dependency injection in aspects

An aspect can now receive a service from dependency injection, for instance from Microsoft.Extensions.DependencyInjection. The aspect returns an <xref:PostSharp.Aspects.Advices.ImportDependencyAdviceInstance> from <xref:PostSharp.Aspects.Advices.IAdviceProvider.ProvideAdvices(System.Object)>, and PostSharp adds a field and a constructor parameter of the service type to the target class and to its derived classes in the project. The advices read the service with <xref:PostSharp.Aspects.Advices.ImportMemberAttribute>. The original constructors are kept as non-public forwarders, so objects created with `new` still compile: they get the service from the new <xref:PostSharp.Extensibility.RunTimeServiceLocator> class. Since this adds a parameter to the public constructors of the target class, it changes the public API of the class. See <xref:constructor-dependencies>.

### Caching with dependency injection

The classes with cached methods can now receive their cache from a dependency injection container. With <xref:PostSharp.Patterns.Caching.CacheConfigurationAttribute.UseDependencyInjection?text=CacheConfiguration.UseDependencyInjection> set to `true`, their constructors receive an <xref:PostSharp.Patterns.Caching.ICachingService>, which the application registers in the container with its backend and its profiles. Each container then has its own cache. The methods that do not receive a service use <xref:PostSharp.Patterns.Caching.CachingServices.DefaultService>, which replaces <xref:PostSharp.Patterns.Caching.CachingServices.DefaultBackend> and <xref:PostSharp.Patterns.Caching.CachingServices.DefaultKeyBuilder>. Static methods and methods of structs cannot receive a service, so they use <xref:PostSharp.Patterns.Caching.CachingServices.DefaultService> and cause the warning <xref:cac011?text=CAC011>, and invalidating a method that uses another caching service causes <xref:cac012?text=CAC012>. See <xref:caching-dependency-injection> and <xref:breaking-changes-20270>.

## Members and fields of the target class

The advices of any aspect, including a statically scoped aspect such as a <xref:PostSharp.Aspects.MethodLevelAspect>, can now work with the state of the target object, which previously required an <xref:PostSharp.Aspects.InstanceLevelAspect>:

* An advice parameter annotated with <xref:PostSharp.Aspects.Advices.ImportMemberAttribute> receives a field or a property of the target class, by value or by reference, an open delegate of a method, or a binding object. See [Importing members of the target type](xref:advice-parameter-binding#importing-members-of-the-target-type).
* An aspect returns an <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance> from <xref:PostSharp.Aspects.Advices.IAdviceProvider.ProvideAdvices(System.Object)> to request a field in the target type, either an existing field or a new one, and its advices read and write this field. See [Requesting fields](xref:advice-provider#requesting-fields).
* <xref:PostSharp.Aspects.Advices.MatchPointcut.IsRequired> makes the build fail when an advice with a <xref:PostSharp.Aspects.Advices.MatchPointcut> applies to no method. See <xref:pointcuts>.

## Support for .NET 11 and C# 15

PostSharp 2027.0 supports the .NET 11 SDK and C# 15, MSBuild 18.9 and 18.10, and Visual Studio 18.9 and 18.10. The supported target frameworks move to .NET 10 and .NET 11, and the .NET 10 SDK is the minimum to build. See <xref:breaking-changes-20270>.

### Runtime async

With `<Features>runtime-async=on</Features>`, the C# compiler implements async methods without a state machine, and the runtime suspends and resumes them. PostSharp 2027.0 applies aspects to these methods. The advices run at the same points and receive the same values as with a state machine. The only difference is that `[CurrentTask]` is `null`, because the runtime provides no task while the method runs.

The following project targets .NET 11 and enables runtime async:

```xml
<PropertyGroup>
  <TargetFramework>net11.0</TargetFramework>
  <Features>runtime-async=on</Features>
</PropertyGroup>
```

## Cross-platform options interface and command line tool

The Windows options application is replaced by a browser-based user interface and by the `postsharp` command line tool. Both are built on the infrastructure engine of Metalama, which is mature and cross-platform, so they work the same on Windows, Linux and macOS.

Install the tool as a .NET global tool:

```powershell
dotnet tool install -g PostSharp.Tool
```

The tool registers license keys, edits the configuration of PostSharp, and reports the state of telemetry:

```powershell
postsharp license register <key>
postsharp license list
postsharp ui
postsharp shutdown
```

`postsharp ui` opens the configuration pages in your browser. On Windows, the toast notifications that PostSharp shows after a build, for instance when a license is about to expire, open the same pages. `postsharp shutdown` stops the PostSharp processes that keep running after a build, such as the pipe server. See <xref:deploying-keys>.

PostSharp 2027.0 also accepts license keys signed with the Elliptic Curve Digital Signature Algorithm (ECDSA), which can be verified on every platform, including macOS with .NET 11. The license keys issued before remain valid.

## Telemetry

Usage reporting (telemetry) is now switched on at the first build, unless you opt out, as in Metalama. A notification informs you when this happens. Crash reports are still sent only after you agree.

To opt out on a machine, set the `POSTSHARP_TELEMETRY_OPT_OUT` environment variable. To opt out for all the builds of a repository, set the `TelemetryEnabled` property in the `postsharp.config` file at the root of the repository:

```xml
<Project xmlns="http://schemas.postsharp.org/1.0/configuration">
  <Property Name="TelemetryEnabled" Value="False" />
</Project>
```

## Build integration

* PostSharp supports the MSBuild server, which the .NET 11 SDK enables by default.
* An unattended build, for instance on a build server, is now licensed for the production mode of PostSharp Logging, so the build server needs no license key for it. See <xref:build-server>.
* `TreatWarningsAsErrors` now applies to the warnings of PostSharp and of aspects. See <xref:ignoring-warnings>.
* The compiler no longer shares its third-party dependencies, such as Newtonsoft.Json, System.Text.Json or System.Collections.Immutable, with the project it compiles. On .NET Framework, a project that references a higher version of one of them no longer fails with <xref:ps0264?text=PS0264>, and the build-time code of the project runs against the versions that the project references. See <xref:breaking-changes-20270>.
* Add-ins compile against the reference assemblies of the new `PostSharp.Sdk` package.

To keep the warnings of PostSharp as warnings in a project that treats the warnings of the compiler as errors, set `PostSharpTreatWarningsAsErrors` to `False`:

```xml
<PropertyGroup>
  <TreatWarningsAsErrors>True</TreatWarningsAsErrors>
  <PostSharpTreatWarningsAsErrors>False</PostSharpTreatWarningsAsErrors>
</PropertyGroup>
```

## Aspect test framework

The new `PostSharp.Testing.AspectTesting` package is a test framework for aspects, based on xunit.v3. Each source file of a test project is a test: the framework compiles it, weaves it with PostSharp in an assembly of its own, verifies the woven code with ILVerify, and runs the program. It can also compare the output of the program and the errors and warnings of its build with expected files. A test can therefore check the errors that an aspect emits when it is misused, as well as its run-time behavior. For details, see <xref:aspect-tests>.

With the `@CompareTransformedCode` directive, a test also checks the code that the aspect generates. The framework decompiles the woven assembly to C# with ICSharpCode.Decompiler, the decompiler engine of ILSpy, and compares the declarations marked with `// <target>`, or all the top-level types of the file, with a `.t.cs` snapshot stored next to the test. As with the other expected files, you accept a new snapshot when the woven code changes intentionally.

## Plugin for AI coding agents

PostSharp 2027.0 provides a plugin for AI coding agents. The plugin supports [Claude Code](https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview) and [OpenAI Codex](https://developers.openai.com/codex). It contains this documentation, the API reference, and scripts that look up an article or an API. The agent can therefore check the real API before it writes PostSharp code. The plugin also instructs the agent to build the project to verify the code.

Install the plugin from the [PostSharp.AI.Skills](https://github.com/postsharp/PostSharp.AI.Skills) marketplace. For instructions, see <xref:ai-agents>.

In Claude Code, for instance, add the marketplace and install the plugin:

```text
/plugin marketplace add https://github.com/postsharp/PostSharp.AI.Skills
/plugin install postsharp
```

## Bug fixes

PostSharp 2027.0 fixes more than 100 bugs, not counting the issues of its own build and tests. Many of these bugs come from the deep backlog, and about a third of them were found by AI agents. The fixes cover the compiler, the aspect framework, the build integration, licensing, and the Pattern Libraries, in particular the caching, logging, threading and model libraries. For the complete list, see the release notes of each build on [GitHub](https://github.com/postsharp/PostSharp.Public/releases).
