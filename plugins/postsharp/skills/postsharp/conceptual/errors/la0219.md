# LA0219: Required Async Call Identifier on a Method That Is Not Async

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is bound by [AsyncCallId] with IsRequired set to true, but "<Target>" is not transformed as an async method.` |

## Cause

A parameter of a method boundary advice annotated with <xref:PostSharp.Aspects.Advices.AsyncCallIdAttribute> receives the <xref:PostSharp.Aspects.AsyncCallId> that identifies the current execution of an async method. The identifier is stored in the state machine of the method, so only a method that becomes an async state machine has one. On another method, the parameter normally receives the default value of <xref:PostSharp.Aspects.AsyncCallId>. When <xref:PostSharp.Aspects.Advices.AsyncCallIdAttribute.IsRequired> is `true`, PostSharp reports LA0219 instead.

PostSharp accepts an `async` method, and a method that returns an awaitable type, such as <xref:System.Threading.Tasks.Task>, for which PostSharp can generate a state machine. It checks again when it generates the code, and also reports LA0219 when the transformation of the method creates no async state machine. The message is reported on the target method, once for each advice that requires the identifier.

## Resolution

* Apply the aspect only to async methods.
* When the advice can work without an identifier, set <xref:PostSharp.Aspects.Advices.AsyncCallIdAttribute.IsRequired> to `false`, which is the default, and test <xref:PostSharp.Aspects.AsyncCallId.IsNull> in the advice.
