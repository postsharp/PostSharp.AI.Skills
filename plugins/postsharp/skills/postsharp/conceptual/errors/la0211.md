# LA0211: Advice Parameter Type Incompatible with the Bound Value

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is of type "<ParameterType>", which cannot receive the value of type "<ValueType>" bound by <Binding>. The parameter must be of type "<ValueType>", or of a base type when "<ValueType>" is a reference type.` |

## Cause

Several binding attributes give a value of a fixed type: <xref:PostSharp.Aspects.Advices.DeclarationIdentifierAttribute> gives a <xref:PostSharp.Reflection.DeclarationIdentifier>, <xref:PostSharp.Aspects.Advices.AsyncCallIdAttribute> an <xref:PostSharp.Aspects.AsyncCallId>, <xref:PostSharp.Aspects.Advices.AwaitedTaskAttribute> a <xref:System.Threading.Tasks.Task>. PostSharp passes the value without converting it, so the parameter must be able to hold it:

* When `<ValueType>` is a value type, the parameter must be of this exact type, because PostSharp does not box the value. An <xref:System.Object> parameter is not accepted.
* When `<ValueType>` is a reference type, the parameter can be of this type or of a base type.

When the parameter type does not follow this rule, PostSharp reports LA0211 on the parameter. `<Binding>` is the binding attribute as you write it, such as `[DeclarationIdentifier]`. The table in [Binding attributes](xref:advice-parameter-binding#binding-attributes) gives the parameter type that each attribute accepts.

Change the type of the parameter to the type of the bound value, `<ValueType>`. When you need the value as an <xref:System.Object>, convert it in the body of the advice.
