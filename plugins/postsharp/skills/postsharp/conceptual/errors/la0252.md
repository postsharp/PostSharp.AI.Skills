# LA0252: Aspect Rejects Its Target in CompileTimeValidate

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The aspect "<Aspect>" cannot be applied to "<Target>": <Reason>` |

## Cause

An aspect checks at build time that it can be applied to its target, in its `CompileTimeValidate` method, such as <xref:PostSharp.Aspects.MethodLevelAspect.CompileTimeValidate(System.Reflection.MethodBase)> for a method-level aspect. To reject the target with an error, the method can throw an <xref:PostSharp.Extensibility.InvalidAnnotationException>. PostSharp then reports LA0252 on the target, without a stack trace, and does not apply the aspect to it.

`<Reason>` is the message of the exception, which the author of the aspect writes. Any other exception thrown by `CompileTimeValidate` is reported as an unexpected exception of the aspect, with its stack trace.

## Resolution

Read the reason in the message, which tells what the aspect requires:

* Remove the aspect from the target, or change the target so that it fits the requirements of the aspect.
* When the aspect is applied by multicasting, exclude the target, for instance with <xref:PostSharp.Extensibility.MulticastAttribute.AttributeExclude> or by narrowing the multicast filters.
* If you are the author of the aspect and the aspect should skip such targets silently, return `false` from `CompileTimeValidate` instead of throwing the exception.
