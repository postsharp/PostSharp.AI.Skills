# PS0120: Multicast Pointcut Selects Declarations with Unsupported Attributes

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Invalid MulticastPointcut attribute on the advice "<Advice>": this kind of advice cannot apply to declarations with the attribute(s) "<Attributes>".` |

## Cause

A <xref:PostSharp.Aspects.Advices.MulticastPointcut> selects the declarations to which an advice of a composite aspect applies. Its <xref:PostSharp.Aspects.Advices.MulticastPointcut.Attributes> property filters these declarations by visibility, scope, virtuality, abstraction and other characteristics. Each kind of advice supports only some of these values. For example, the advices of methods (<xref:PostSharp.Aspects.Advices.OnMethodEntryAdvice>, <xref:PostSharp.Aspects.Advices.OnMethodInvokeAdvice>...) and of locations cannot apply to abstract members, which have no body, and the advices of locations cannot apply to literal fields (constants).

PostSharp reports PS0120, on the advice method `<Advice>`, when <xref:PostSharp.Aspects.Advices.MulticastPointcut.Attributes> contains a value that the advice does not support. `<Attributes>` lists these values, as <xref:PostSharp.Extensibility.MulticastAttributes> flags.

## Resolution

* Remove the unsupported values from <xref:PostSharp.Aspects.Advices.MulticastPointcut.Attributes>, for example replace <xref:PostSharp.Extensibility.MulticastAttributes.AnyAbstraction> with <xref:PostSharp.Extensibility.MulticastAttributes.NonAbstract>.
* Otherwise, do not set the abstraction or literality category of <xref:PostSharp.Aspects.Advices.MulticastPointcut.Attributes>: PostSharp then uses the values that the advice supports for every category that you leave unset.
