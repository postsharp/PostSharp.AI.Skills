# LA0045: InitializeAspects Method of a Base Class Is Private

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The call to AspectUtilities.InitializeCurrentAspects in type "<CallingType>" cannot invoke the method "<Method>" because this method is private. Make this method protected.` |

## Cause

PostSharp replaces each call to <xref:PostSharp.Aspects.AspectUtilities.InitializeCurrentAspects> with a call to the `InitializeAspects` method of the current object. It looks for this method in the class that contains the call, and then in its base classes. You can declare `InitializeAspects` yourself, typically in the root class of a hierarchy, so that the aspects of all the derived classes can be initialized when an object is created without a constructor.

When the method that PostSharp finds is private and declared in a base class, the calling class cannot invoke it, and PostSharp reports LA0045. `<Method>` is the `InitializeAspects` method of the base class, and `<CallingType>` is the class that contains the call to <xref:PostSharp.Aspects.AspectUtilities.InitializeCurrentAspects>. The message is reported on the line of the call.

## Resolution

Declare `InitializeAspects` as `protected virtual void InitializeAspects()`, as described in <xref:instance-initialization>. A protected method can be called from the derived classes, and a virtual method lets PostSharp override it in the derived classes that have aspects. The article also lists the other constraints on this method.
