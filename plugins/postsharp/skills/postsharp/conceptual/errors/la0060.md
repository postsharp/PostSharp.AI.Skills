# LA0060: Introduced Member Already Exists in the Target Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot introduce member "<Member>" into type "<TargetType>" because it is already defined in type "<DeclaringType>".` |

## Cause

An aspect introduces a method, a property or an event into its target type with <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute>. When the target type already defines a member with the same name and signature, PostSharp follows the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> of the introduction. Its default value, <xref:PostSharp.Aspects.Advices.MemberOverrideAction.Fail>, reports LA0060 instead of replacing the existing member, so that the aspect does not silently change code that you wrote.

`<DeclaringType>` is the type that defines the existing member: the target type itself, or one of its base types.

## Resolution

Choose what the aspect does when the member already exists, with the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> property of the introduction:

* <xref:PostSharp.Aspects.Advices.MemberOverrideAction.Ignore> keeps the existing member and skips the introduction.
* <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrFail> replaces the existing member with the introduced one, or overrides it when a base type defines it. The two members must be compatible: for example, PostSharp reports <xref:la0072?text=LA0072> when their visibility differs, and an error when the member of the base type is sealed or not virtual.
* <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrIgnore> also overrides the existing member, but skips the introduction instead of failing when the member of the base type cannot be overridden.

Otherwise, rename the existing member or the introduced one.
