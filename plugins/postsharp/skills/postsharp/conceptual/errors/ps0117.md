# PS0117: Aspect Initialization Method of a Public Class Is Not Overridable

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The method "<Method>" must be "public virtual" or "protected virtual", and not sealed, because PostSharp uses it to initialize aspects and its declaring type is visible outside the assembly.` |

## Cause

To initialize the instance-scoped aspects of a class, PostSharp generates two methods without parameters in this class, `InitializeAspects` and `OnInstanceConstructed`, and calls them when an instance is constructed. `OnInstanceConstructed` exists when an aspect has an <xref:PostSharp.Aspects.Advices.OnInstanceConstructedAdvice>. When the class already defines a method with one of these names and signatures, PostSharp uses it instead of generating one, and adds its code to it.

A derived class, possibly in another assembly, must be able to override this method to initialize its own aspects. So when the declaring type is visible outside the assembly and is not sealed, PostSharp reports PS0117 when the method `<Method>` is not virtual, is sealed, or is not visible outside the assembly (`private` or `internal`).

## Resolution

* Make the method `protected virtual` or `public virtual`, and do not seal it. PostSharp then adds its code to your method, after your code, and calls the method when an instance is constructed.
* Otherwise, rename the method, so that PostSharp generates its own one. Do this when your method is not meant to run at construction time.
* When the class does not need derived classes, make it `sealed`: the rule then does not apply.
