# LA0248: Exception Advice Can Replace the Exception in Two Ways

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The advice "<Advice>" has both a MethodExecutionArgs parameter and the [Exception] parameter "<Parameter>", passed as out or ref. With FlowBehavior.ThrowException, the value of the [Exception] parameter is thrown, and MethodExecutionArgs.Exception is ignored.` |

## Cause

In an <xref:PostSharp.Aspects.Advices.OnMethodExceptionAdvice>, a parameter annotated with <xref:PostSharp.Aspects.Advices.ExceptionAttribute> and passed as `out` or `ref` is the variable that holds the caught exception. When the advice sets <xref:PostSharp.Aspects.FlowBehavior.ThrowException?text=FlowBehavior.ThrowException>, PostSharp throws the value of this variable.

When the same advice also has a <xref:PostSharp.Aspects.MethodExecutionArgs> parameter, the advice can set the exception to throw in a second place, the <xref:PostSharp.Aspects.MethodExecutionArgs.Exception> property, which PostSharp then ignores. PostSharp reports LA0248 on the `[Exception]` parameter as soon as the advice has both parameters, whether or not it sets the property, so that a replacement written to the property is not lost silently.

`<Advice>` is the advice method, with its parameter types, and `<Parameter>` is the name of the `[Exception]` parameter.

## Resolution

Read and replace the exception in one place only:

* Remove the `[Exception]` parameter, and read and set <xref:PostSharp.Aspects.MethodExecutionArgs.Exception>. With `FlowBehavior.ThrowException`, PostSharp then throws the value of the property.
* Or remove the <xref:PostSharp.Aspects.MethodExecutionArgs> parameter, and bind the other values that the advice needs with their own parameters: <xref:PostSharp.Aspects.Advices.FlowBehaviorAttribute> for the flow behavior, <xref:PostSharp.Aspects.Advices.DeclarationAttribute> for the target method.
