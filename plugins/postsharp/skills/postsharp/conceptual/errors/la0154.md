# LA0154: FlowBehavior.Yield Not Available Without an Awaiter Parameter

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `Advice "<Advice>" cannot apply FlowBehavior.Yield to the async method "<Method>" because it does not have an [Awaiter] parameter.` |

## Cause

In an async method, an <xref:PostSharp.Aspects.Advices.OnMethodEntryAdvice> or an <xref:PostSharp.Aspects.Advices.OnMethodResumeAdvice> can set its <xref:PostSharp.Aspects.Advices.FlowBehaviorAttribute> parameter to <xref:PostSharp.Aspects.FlowBehavior.Yield?text=FlowBehavior.Yield>, so that the method awaits an awaiter of the aspect before it continues. The awaiter comes from a parameter annotated with <xref:PostSharp.Aspects.Advices.AwaiterAttribute>. When the advice has a `[FlowBehavior]` parameter but no `[Awaiter]` parameter, PostSharp does not weave the code that yields, and reports LA0154 on the async method `<Method>`, once for each such advice.

PostSharp reports the warning whatever value the advice sets: also an advice that only uses <xref:PostSharp.Aspects.FlowBehavior.Return?text=FlowBehavior.Return>, for instance to return a cached value, causes it.

## Resolution

* When the advice must make the method yield, add an `[Awaiter]` parameter passed as `out`, and assign it an awaiter, such as the one that `Task.Yield().GetAwaiter()` returns.
* When the advice never sets `FlowBehavior.Yield`, the warning does not affect the woven code, and you can ignore it.
