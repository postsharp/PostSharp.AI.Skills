# PS0136: Unmatched or Empty Curly Bracket in an Expression

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Invalid expression "<Expression>": the bracket at position <Position> has no matching bracket or encloses no expression.` |

## Cause

Many attributes of a `postsharp.config` file, such as the `Value` of a `Property` element, the `File` of a `Using` element or the `Condition` of most elements, accept expressions. PostSharp evaluates each substring between curly brackets, such as `{$AssemblyName}`, as an XPath expression, and copies the rest of the attribute as it is. See <xref:configuration-xpath>.

PostSharp reports PS0136 when the attribute has:

* an opening curly bracket `{` with no closing `}` after it;
* a closing curly bracket `}` with no opening `{` before it;
* a pair of curly brackets with nothing but white space between them, such as `{}`.

`<Expression>` is the whole value of the attribute, and `<Position>` is the position of the bracket in it, starting at 1: the opening bracket of an unclosed or empty pair, or the lone closing bracket. The location of the message is the element of the configuration file. PostSharp does not evaluate the attribute. Because the configuration of the project has an error, PostSharp then stops with <xref:ps0084?text=PS0084>.

## Resolution

* Add the missing bracket, or remove the stray one.
* Write an expression between the brackets of an empty pair, or remove the pair.
* When the attribute must contain a literal curly bracket, double it: PostSharp reads `{{` as `{` and `}}` as `}`.
