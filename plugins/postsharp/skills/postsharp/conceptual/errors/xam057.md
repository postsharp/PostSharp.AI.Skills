# XAM057: Property Change Handler Named by the Aspect Does Not Exist

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Xaml |
| **Message** | `Error in the [<Aspect>] aspect applied to property <Property>: type <DeclaringType> does not declare any method named "<Method>".` |

## Cause

The <xref:PostSharp.Patterns.Xaml.DependencyPropertyAttribute> and <xref:PostSharp.Patterns.Xaml.AttachedPropertyAttribute> aspects call a change handler method after the value of the property changes. By default, they look for an optional method named `On` followed by the name of the property and `Changed`, such as `OnQuantityChanged`. When you set the <xref:PostSharp.Patterns.Xaml.DependencyPropertyBaseAttribute.PropertyChangedMethod> property of the aspect, the aspect looks for a method with exactly this name instead, and reports XAM057 when the class does not have one.

The aspect searches the methods of any visibility, static or instance, but only those that the class of the property itself declares: a method inherited from a base class is not found. PostSharp reports the message on the property.

The current version of the message says that the method "is not accessible", which is misleading: the class does not declare the method, and the aspect never checks accessibility.

## Resolution

* Correct the name in <xref:PostSharp.Patterns.Xaml.DependencyPropertyBaseAttribute.PropertyChangedMethod>. Use the `nameof` operator rather than a string literal, so that the C# compiler checks the name and a rename updates it.
* When the method is declared in a base class, declare it in the class of the property, for example as a method that calls the method of the base class.
* Remove <xref:PostSharp.Patterns.Xaml.DependencyPropertyBaseAttribute.PropertyChangedMethod> and name the method by the convention, such as `OnQuantityChanged`.
