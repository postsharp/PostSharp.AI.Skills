# THR040: Access Level Attribute Applied to a Static Method

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `The [<ThreadingModel>] threading model ignores the access level attribute of "<Method>" because it is a static method. Access level attributes, such as [Reader] and [Writer], apply only to instance methods.` |

## Cause

The access level attributes, <xref:PostSharp.Patterns.Threading.ReaderAttribute>, <xref:PostSharp.Patterns.Threading.WriterAttribute>, <xref:PostSharp.Patterns.Threading.UpgradeableReaderAttribute> and <xref:PostSharp.Patterns.Threading.YielderAttribute>, specify the lock that a method acquires on the object, for example under the <xref:PostSharp.Patterns.Threading.ReaderWriterSynchronizedAttribute> threading model. The lock belongs to an instance, so a static method, which has no instance, cannot acquire it.

When the threading model of a class analyzes its members, it reports THR040 for each static method of the class that has an access level attribute, and ignores the attribute. `<ThreadingModel>` is the name of the threading model aspect of the class, for example `ReaderWriterSynchronizedAttribute`.

## Resolution

* When the static method does not access the state of an instance, as `FormatPrice` does not, remove the attribute.
* When the method reads or writes the fields of an instance, make it an instance method, so that the attribute acquires the lock of that instance.
* When the method accesses static state, protect it with another mechanism: the threading models do not synchronize static fields.
