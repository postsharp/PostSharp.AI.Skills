# THR037: Background Method in an Actor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Cannot add [Background] to method "<Method>" because the [Actor] threading model is applied to the type "<Type>". Apply [Background] to a static method, or to a method of another type.` |

## Cause

The <xref:PostSharp.Patterns.Threading.ActorAttribute> threading model executes the methods of an actor one at a time, in the context of the actor, so that the actor never needs a lock. The <xref:PostSharp.Patterns.Threading.BackgroundAttribute> aspect executes a method in a thread of the thread pool, outside of this context. An instance method of an actor with this aspect could therefore access the state of the actor concurrently with its other methods, so PostSharp reports THR037.

The check applies only to instance methods. A static method does not access the state of an actor, so it can have the <xref:PostSharp.Patterns.Threading.BackgroundAttribute> aspect.

In the following example, the `BuildReportAsync` instance method of the `OrderProcessor` actor has the <xref:PostSharp.Patterns.Threading.BackgroundAttribute> aspect. The `async` instance methods of the actor also have the <xref:PostSharp.Patterns.Threading.ReentrantAttribute> attribute, which the <xref:PostSharp.Patterns.Threading.ActorAttribute> threading model requires (<xref:thr017?text=THR017>).

## Resolution

* When the background work does not need the state of the actor, make the method `static` and pass it the data it needs as parameters.
* When the method needs the state of the actor, remove the <xref:PostSharp.Patterns.Threading.BackgroundAttribute> aspect: the caller of a public `async` method of an actor does not wait for the method to execute in the context of the actor.
* Otherwise, move the background work to a method of another class.
