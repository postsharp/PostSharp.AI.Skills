# LA0130: Aspect Applied to an Interface Method Without Implementation

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Aspect "<Aspect>" cannot be applied to method "<Method>" because it is an interface method without a default implementation.` |

## Cause

An <xref:PostSharp.Aspects.OnMethodBoundaryAspect>, an <xref:PostSharp.Aspects.OnExceptionAspect> or a <xref:PostSharp.Aspects.MethodInterceptionAspect> enhances the body of its target method, or redirects its calls to the aspect. A method of an interface that has no default implementation has no body, and the calls through the interface go to the classes that implement it. When one of these aspects targets such a method of the current project, PostSharp reports LA0130 and skips the aspect. An interface method with a default implementation, available since C# 8, is a valid target.

The usage of these aspect classes excludes abstract methods, so when you apply them as custom attributes, multicasting skips the interface methods without a default implementation. An aspect that an <xref:PostSharp.Aspects.IAspectProvider> provides is not filtered this way: its target is the declaration passed to the <xref:PostSharp.Aspects.AspectInstance> constructor. PostSharp then reports the message on the declaration that the provider is applied to.

## Resolution

* In the <xref:PostSharp.Aspects.IAspectProvider.ProvideAspects*> method, skip the methods whose <xref:System.Reflection.MethodBase.IsAbstract> property is `true`.
* To enhance every implementation of the interface method, apply the aspect to the classes that implement the interface instead of the interface itself.
