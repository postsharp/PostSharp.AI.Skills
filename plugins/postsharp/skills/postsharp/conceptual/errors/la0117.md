# LA0117: Aspect Provider Returns an Invalid Object Construction

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot parse the ObjectConstruction provided by the aspect provider "<AspectProvider>" applied on "<Target>".` |

## Cause

An <xref:PostSharp.Aspects.IAspectProvider> can describe the aspect that it provides with an <xref:PostSharp.Reflection.ObjectConstruction> instead of an instance: the type of the aspect, the arguments of its constructor, and the values of its properties or fields. PostSharp then builds a custom attribute from this description. The <xref:PostSharp.Reflection.ObjectConstruction> is not checked when you create it from a type name or a <xref:System.Type>, so a mistake shows up only at build time:

* No constructor of the aspect takes the given number and types of arguments. PostSharp also reports <xref:ps0202?text=PS0202>, which gives the type and the types of the arguments.
* A named argument is neither a property nor a field of the aspect. PostSharp also reports <xref:ps0121?text=PS0121>, which gives the name.

PostSharp then reports LA0117, which names the aspect provider and the target `<Target>` of the aspect, and skips the aspect. The message points to the aspect provider.

## Resolution

Make the <xref:PostSharp.Reflection.ObjectConstruction> match the aspect class: pass the arguments of an existing constructor, in the right order and with the right types, and name only properties or fields of the aspect in <xref:PostSharp.Reflection.ObjectConstruction.NamedArguments>. To get these checks when the provider runs, create the <xref:PostSharp.Reflection.ObjectConstruction> from a <xref:System.Reflection.ConstructorInfo>, or provide an aspect instance instead.
