# LA0160: Aspect Providers Provide Aspects Without End

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `A cycle was detected while executing IAspectProvider instances. The following aspects may be part of the cycle: "<AspectTypes>".` |

## Cause

An aspect that implements <xref:PostSharp.Aspects.IAspectProvider> adds other aspects to the code with its <xref:PostSharp.Aspects.IAspectProvider.ProvideAspects(System.Object)> method. PostSharp discovers aspects in rounds: it initializes the aspects found in a round, and the aspects that they provide form the next round. When the aspects keep providing new aspects for more than 64 rounds, PostSharp assumes that the providers form a cycle, stops, and reports LA0160.

The typical cause is two aspect providers that provide each other, or an aspect provider that provides a new instance of itself. Each round then provides new instances of the same aspects.

`<AspectTypes>` lists, separated by semicolons, the aspect types that implement <xref:PostSharp.Aspects.IAspectProvider> among the aspects of the last round. It may not name every aspect of the cycle. The message is reported on the first of these types.

## Resolution

Make sure that the chain of provided aspects ends: an aspect must not provide, directly or through other aspects, an aspect of its own type on the same target. When two aspects should always go together, let one of them provide the other, and apply only that one.
