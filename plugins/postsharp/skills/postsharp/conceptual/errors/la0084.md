# LA0084: Advice Attribute Not on a Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Advice "<Advice>" is not valid on "<Declaration>": this custom attribute is valid only on methods.` |

## Cause

The advices that transform the target code, such as <xref:PostSharp.Aspects.Advices.OnMethodEntryAdvice>, <xref:PostSharp.Aspects.Advices.OnLocationGetValueAdvice>, <xref:PostSharp.Aspects.Advices.OnEventAddHandlerAdvice> or <xref:PostSharp.Aspects.Advices.LocationValidationAdvice>, are methods of the aspect class: the custom attribute marks the method that PostSharp invokes. PostSharp reads advice attributes on every member of the aspect class and on the class itself, and reports LA0084 when one of these attributes is on a declaration that is not a method.

The built-in advice attributes can be applied only to methods, so the C# compiler usually reports the mistake first. <xref:PostSharp.Aspects.Advices.LocationValidationAdvice> is not sealed, though: a class derived from it can declare an <xref:System.AttributeUsageAttribute> that allows other targets, and PostSharp handles it as a location validation advice. `<Advice>` is the type of the custom attribute, and `<Declaration>` is the declaration that carries it.

## Resolution

Apply the advice attribute to the method that implements the advice. If you derive an advice attribute from <xref:PostSharp.Aspects.Advices.LocationValidationAdvice>, restrict its <xref:System.AttributeUsageAttribute> to `AttributeTargets.Method`, so that the C# compiler rejects any other target.
