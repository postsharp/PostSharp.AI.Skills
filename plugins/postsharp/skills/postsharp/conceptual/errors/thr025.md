# THR025: Type Has No Threading Model

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Thread-safety policy: type <Type> must be assigned to a threading model or marked as [ExplicitlySynchronized].` |

## Cause

When you add the <xref:PostSharp.Patterns.Threading.ThreadSafetyPolicy> attribute to an assembly, PostSharp checks every class of the assembly, including nested classes, and reports THR025 for each class that it does not consider thread-safe. A class is thread-safe for the policy when:

* it has no instance fields;
* it has a threading model, that is an aspect derived from <xref:PostSharp.Patterns.Threading.ThreadAwareAttribute> such as <xref:PostSharp.Patterns.Threading.SynchronizedAttribute> or <xref:PostSharp.Patterns.Threading.ThreadAffineAttribute>;
* it is marked as <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute>;
* the type analyzer of the threading library recognizes it as immutable, for example because all its fields are read-only and of immutable types.

The policy does not check structs, custom attribute classes and compiler-generated types. THR025 is a warning: the policy reminds you to choose a threading model for each class, but does not change the code.

## Resolution

* Apply a threading model to the class, for example <xref:PostSharp.Patterns.Threading.SynchronizedAttribute>, <xref:PostSharp.Patterns.Threading.ReaderWriterSynchronizedAttribute>, <xref:PostSharp.Patterns.Threading.ActorAttribute> or <xref:PostSharp.Patterns.Threading.ThreadAffineAttribute>. The threading model then enforces the rules of thread safety.
* When the class synchronizes the access to its fields in its own code, for example with a `lock` statement, mark it as <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute>.
