# LA0190: Aspect Target Uses a Ref Struct

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to target "<Target>": the target is or uses the ref struct "<RefStruct>", which aspects do not support. Set the UnsupportedTargetAction property of the aspect to Ignore to skip such targets.` |

## Cause

A ref struct, such as <xref:System.Span`1> or <xref:System.ReadOnlySpan`1>, can only live on the stack: it cannot be boxed, stored in a field of a class, or passed to the objects, such as <xref:PostSharp.Aspects.MethodExecutionArgs>, that the code of an aspect receives. PostSharp does not apply aspects to declarations that use a ref struct, and reports LA0190 when:

* the target is a member of a ref struct;
* the target is a method whose return type or a parameter type is a ref struct;
* the target is a property or a field of a ref struct type;
* the target is an event whose delegate has a ref struct parameter or return type.

`<RefStruct>` is the ref struct that PostSharp found: the declaring type, or the type of the return value, parameter or location.

Multicasting often causes this message: an aspect applied to a class reaches every method of the class, including the methods that take a span. ## Resolution

* Set the <xref:PostSharp.Aspects.Aspect.UnsupportedTargetAction> property of the aspect to <xref:PostSharp.Aspects.UnsupportedTargetAction.Ignore>, so that the aspect skips the declarations that use a ref struct without an error. You can set it where you apply the aspect, or in the constructor of the aspect class.
* Exclude the declaration from the multicast, for example with the <xref:PostSharp.Extensibility.MulticastAttribute.AttributeExclude> property on a second instance of the aspect applied to the declaration.
* Apply the aspect to a member that does not use the ref struct, such as an overload that takes a `string`.
