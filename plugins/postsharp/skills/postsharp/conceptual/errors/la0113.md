# LA0113: Method Interception Aspect Applied to an Instance Constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to the instance constructor of type "<Type>": a method interception aspect cannot be applied to an instance constructor. Restrict the aspect to methods, for example with the AttributeTargetElements property.` |

## Cause

A <xref:PostSharp.Aspects.MethodInterceptionAspect> replaces the body of its target method with a call to <xref:PostSharp.Aspects.MethodInterceptionAspect.OnInvoke*>, which decides whether to proceed to the original method. PostSharp does not support this transformation on constructors: it reports LA0113 instead of weaving the aspect into an instance constructor.

The usual cause is multicasting: when you apply the aspect to a class, PostSharp applies it to the members that the aspect accepts, and <xref:PostSharp.Aspects.MethodInterceptionAspect> accepts both methods and instance constructors. PostSharp also reports LA0113 when an <xref:PostSharp.Aspects.IAspectProvider> provides the aspect to a constructor, or when an <xref:PostSharp.Aspects.Advices.OnMethodInvokeAdvice> targets a constructor.

`<Type>` is the type that declares the constructor. When the aspect is multicast from a class, the message points to the class.

## Resolution

Restrict the aspect to methods:

* Set the <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetElements> property of the aspect to <xref:PostSharp.Extensibility.MulticastTargets.Method> where you apply it to a class.
* When an <xref:PostSharp.Aspects.IAspectProvider> provides the aspect, skip the constructors in its `ProvideAspects` method.
