# PS0106: Attribute Applied to an Excluded Kind of Parameter

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the custom attribute "<AttributeType>" to parameter "<Parameter>" of method "<Method>": the attribute does not accept this kind of parameter (<ParameterKind>).` |

## Cause

The <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetParameterAttributes> property of a multicast attribute filters the parameters to which the attribute applies by the way they are passed: <xref:PostSharp.Extensibility.MulticastAttributes.InParameter>, <xref:PostSharp.Extensibility.MulticastAttributes.OutParameter> or <xref:PostSharp.Extensibility.MulticastAttributes.RefParameter>. When the attribute is multicast from a method or a type, PostSharp skips the parameters that the filter excludes. When the attribute is applied directly to an excluded parameter, PostSharp cannot skip it silently, and reports PS0106.

`<ParameterKind>` is the kind of the parameter that the filter excludes: `out parameter`, `ref parameter`, or `input-only parameter`, which also covers `in` parameters. The message has no location in the source code: it names the parameter and its method.

## Resolution

* Remove the attribute from the parameter that the filter excludes.
* When the attribute must apply to this parameter, add its kind to the <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetParameterAttributes> property, or remove the property. A validation aspect must then support this kind of parameter: an `out` parameter has no value when the method starts.
* To apply the attribute to all the parameters of a kind, apply it to the method with the filter, and let PostSharp multicast it to the matching parameters.
