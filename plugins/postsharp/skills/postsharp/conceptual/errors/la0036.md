# LA0036: Aspect Library Not Processed by PostSharp

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `Missing optimization information on method '<Method>'. This information is computed automatically by PostSharp. Make sure that assembly <Assembly> is processed by PostSharp.` |

## Cause

When PostSharp builds the assembly that defines an aspect, it analyzes each advice method, such as <xref:PostSharp.Aspects.OnMethodBoundaryAspect.OnEntry*>, to find which parts of the advice arguments the method uses, and stores the result in a custom attribute on the method. When another project applies the aspect, PostSharp reads this attribute to generate only the code that the advice needs.

PostSharp reports LA0036 when an advice method of an aspect from a referenced assembly does not have this attribute, because the assembly was built without PostSharp: its project references the `PostSharp.Redist` package but not the `PostSharp` package, or it sets the `SkipPostSharp` MSBuild property to `True`. The warning is reported on the advice method. PostSharp still applies the aspect, but without the optimizations.

## Resolution

Build the project that defines the aspect with PostSharp: add a reference to the `PostSharp` package, and remove the `SkipPostSharp` property if the project sets it. See <xref:postsharp-components> and <xref:msbuild-properties>.
