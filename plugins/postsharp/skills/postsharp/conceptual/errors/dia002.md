# DIA002: Logging Aspect Applied to an Abstract Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Diagnostics |
| **Message** | `Cannot apply the [Log] aspect to method '<Method>' because it is abstract.` |

## Cause

The <xref:PostSharp.Patterns.Diagnostics.LogAttribute> aspect, and any other aspect derived from <xref:PostSharp.Patterns.Diagnostics.LogAttributeBase>, logs the execution of a method by adding code to its body. An abstract method, including a method of an interface, has no body, so PostSharp reports DIA002 instead of logging it.

When you add the aspect with an attribute, PostSharp skips abstract methods: the aspect excludes them from multicasting, and an attribute written directly on an abstract method is reported as <xref:ps0091?text=PS0091>. DIA002 therefore comes from code that adds the aspect programmatically, typically an aspect that implements <xref:PostSharp.Aspects.IAspectProvider> and returns an <xref:PostSharp.Aspects.AspectInstance> for every method of a type without checking whether it is abstract.

## Resolution

Skip abstract methods in the code that adds the aspect, for example by testing <xref:System.Reflection.MethodBase.IsAbstract> in the <xref:PostSharp.Aspects.IAspectProvider.ProvideAspects*> method of the aspect provider. Log the methods that override the abstract method instead: they have a body.
