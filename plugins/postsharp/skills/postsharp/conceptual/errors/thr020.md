# THR020: Child Has No Threading Model

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `The type of field <Field> is not compatible with the [<Aspect>] aspect: the type is not immutable and has no threading model. Consider adding a threading model to the type, using [AssumeImmutable], or registering a TypeAdapter for this type.<Note>` |

## Cause

An object with a threading model, such as <xref:PostSharp.Patterns.Threading.SynchronizedAttribute> or <xref:PostSharp.Patterns.Threading.ActorAttribute>, also protects its children, the objects that it references from fields annotated with <xref:PostSharp.Patterns.Model.ChildAttribute>. It can protect a child only when the type of the child is immutable or has a threading model of its own: the methods of a plain class do not take the lock of the parent and are not verified, so another thread could modify the child while the parent holds its lock.

PostSharp reports THR020 when, after all aspects have been discovered, the type of a child field is not immutable and has no threading model. `<Aspect>` is the name of the aspect class of the parent. `<Note>` is usually empty; it explains that an [<xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute>] attribute applied to the backing field of an automatic property has no effect, when that is the case. When the type of the field is a collection that PostSharp cannot enhance, such as `List<T>`, PostSharp reports <xref:com008?text=COM008> instead.

## Resolution

* Add a threading model to the type of the child that is compatible with the model of the parent, as listed in <xref:threading-model-compatibility>.
* When the type is immutable but PostSharp cannot prove it, apply <xref:PostSharp.Patterns.Threading.AssumeImmutableAttribute> to the type, or to the assembly for a type of another assembly.
* When the field references an object that the parent does not own, annotate it with <xref:PostSharp.Patterns.Model.ReferenceAttribute> instead of <xref:PostSharp.Patterns.Model.ChildAttribute>.
* When you synchronize the access to the field yourself, annotate the field or its property with <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute>.
