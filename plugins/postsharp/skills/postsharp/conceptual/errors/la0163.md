# LA0163: Instance-Scoped Aspect Applied to a Declaration of Another Assembly

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the instance-scoped aspect "<Aspect>" to "<Target>" because this declaration is in module "<Module>", not in the module being processed. Apply the aspect to a declaration of the current module instead, for example to an override of the method.` |

## Cause

An instance-scoped aspect, which implements <xref:PostSharp.Aspects.IInstanceScopedAspect>, has one aspect instance for each instance of the target class, created when the class is instantiated. PostSharp adds the code that creates and stores these aspect instances to the class that declares the target. It can only modify the assembly that it is processing, so it cannot apply an instance-scoped aspect to a member declared in another assembly, `<Module>`.

A custom attribute cannot be placed on a member of another assembly, so the target usually comes from an <xref:PostSharp.Aspects.IAspectProvider>: reflection methods such as `Type.GetMethod` also return the members that a class inherits, including those of a base class defined in a library.

In the following example, the `[TrackCommand]` aspect provider gives an instance-scoped `[CountExecutions]` aspect to the `Execute` method of `SaveCommand`. `SaveCommand` does not override `Execute`, so `GetMethod` returns the method of `CommandBase`, which is defined in a library.

## Resolution

* Override the member in a class of the current project, and apply the aspect to the override. A reflection method such as `Type.GetMethod` then returns the override.
* In an aspect provider, skip the members of other assemblies, for example by comparing the `Module` of the member with the `Module` of the target type, or by passing `BindingFlags.DeclaredOnly` to the reflection method.
* If the aspect does not need state for each instance, do not implement <xref:PostSharp.Aspects.IInstanceScopedAspect>. PostSharp can then apply some aspects, such as a <xref:PostSharp.Aspects.MethodInterceptionAspect>, to a method of another assembly by modifying the calls to the method in the current assembly. For a virtual method, PostSharp warns that this is not fully supported (<xref:la0183?text=LA0183>).
