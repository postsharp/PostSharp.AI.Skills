# THR026: Static Field Is Not Read-Only

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Thread-safety policy: static field <Field> must be read-only, or be marked as [ExplicitlySynchronized] or [ThreadStatic].` |

## Cause

A static field is shared by all threads. When any thread can assign it, two threads can see different values, or a thread can see a value that another thread has only partly initialized. When you add the <xref:PostSharp.Patterns.Threading.ThreadSafetyPolicy> attribute to an assembly, PostSharp therefore checks the static fields of every class and reports THR026 for each static field that is not `readonly`.

The policy does not check constants, compiler-generated fields, such as the backing field of a static automatic property, fields marked as <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute> and fields marked as <xref:System.ThreadStaticAttribute>. A field that is not read-only and whose type is not thread-safe also gets <xref:thr027?text=THR027>.

## Resolution

* When the field does not change after its initialization, make it `readonly`.
* When the program must change the field, and every access to it is synchronized in your code, for example with a `lock` statement, mark it as <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute>.
* When each thread needs its own value, mark the field as <xref:System.ThreadStaticAttribute>.
