# THR019: Child Has an Incompatible Threading Model

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `The type of field <Field> is not compatible with the [<Aspect>] aspect: objects with threading model "<ChildModel>" cannot be children of objects with threading model "<ParentModel>".` |

## Cause

An object with a threading model, such as <xref:PostSharp.Patterns.Threading.FreezableAttribute> or <xref:PostSharp.Patterns.Threading.SynchronizedAttribute>, also protects its children, the objects that it references from fields annotated with <xref:PostSharp.Patterns.Model.ChildAttribute>. A child either shares the concurrency controller of its parent, such as its lock, or keeps its own. Some combinations of models cannot work together: for example, a synchronized object cannot be frozen, and an actor does not take the locks that a synchronized child needs. The article <xref:threading-model-compatibility> lists which models can be children of which.

PostSharp reports THR019 when the type of a child field has a threading model that cannot be a child of the threading model of the class. `<Aspect>` is the name of the aspect class of the parent, `<ChildModel>` is the threading model of the type of the field, and `<ParentModel>` is the threading model of the class.

## Resolution

* Give the type of the child a threading model that is compatible with the model of the parent, as listed in <xref:threading-model-compatibility>. For a freezable or immutable parent, the child must be freezable or immutable.
* When the field references an object that the parent does not own, annotate it with <xref:PostSharp.Patterns.Model.ReferenceAttribute> instead of <xref:PostSharp.Patterns.Model.ChildAttribute>.
