# PS0093: Invalid Regular Expression in a Multicast Filter

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Invalid expression for property <Property> of the custom attribute "<AttributeType>" on <DeclarationKind> "<Declaration>": <Error>` |

## Cause

The properties of <xref:PostSharp.Extensibility.MulticastAttribute> that filter targets by name, <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetTypes>, <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetMembers>, <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetParameters> and <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetAssemblies>, as well as the <xref:PostSharp.Aspects.Advices.MulticastPointcut.MemberName> property of a pointcut, accept a name, a pattern with the `*` wildcard, or a regular expression when the value starts with the `regex:` prefix. PostSharp reports PS0093 when the text after the `regex:` prefix is not a valid .NET regular expression.

`<Property>` is the property that contains the expression, `<Declaration>` is the declaration that the attribute is applied to, and `<Error>` is the reason given by the .NET regular expression parser, including the position of the problem in the expression. When the expression is in a multicast attribute, PostSharp then stops the build with <xref:ps0055?text=PS0055>, because it does not continue after an error in the multicast attributes.

## Resolution

Correct the regular expression, as `<Error>` describes. In C#, a backslash in a regular expression must be doubled in a regular string literal, or written in a verbatim string literal (`@"regex:..."`). When you do not need a regular expression, use a name with the `*` wildcard and without the `regex:` prefix.
