# SR0006: Base Type of a PSerializable Type Is Not Serializable

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply [PSerializable] to type '<Type>' because its base type is not serializable: it has neither a [PSerializable] or [Serializer] attribute nor a nested Serializer class. Apply [PSerializable] to the base type.` |

## Cause

[<xref:PostSharp.Serialization.PSerializableAttribute>] generates a serializer for `<Type>` that serializes the fields declared in `<Type>`, and extends the serializer of the base type for the fields that the base type declares. The base type must therefore have a serializer, given by one of:

* [<xref:PostSharp.Serialization.PSerializableAttribute>], which generates it;
* [<xref:PostSharp.Serialization.SerializerAttribute>], which names a serializer written by hand, or no serializer with `[Serializer(null)]` when the base type has no state to serialize;
* a nested class named `Serializer`, written by hand.

The base types <xref:System.Object>, <xref:System.ValueType>, <xref:System.Attribute> and <xref:System.MarshalByRefObject> do not need a serializer. PostSharp reports SR0006 when the direct base type of `<Type>` is another type that has none of the three. This includes most classes of .NET and of other libraries.

## Resolution

* Apply [<xref:PostSharp.Serialization.PSerializableAttribute>] to the base type. PostSharp then generates its serializer, which the serializer of the derived type extends.
* When the base type has no state to serialize, mark it with `[Serializer(null)]`, and give it a parameterless constructor that the derived type can access.
* When you cannot change the base type, for example because it is a class of another library, do not derive from it: keep an instance of it in a field, write a serializer for its type, and declare this serializer with <xref:PostSharp.Serialization.ImportSerializerAttribute>.
