# LA0067: Type-Level Dependency on an Advice

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot define <Level>-level dependencies on the advice "<Advice>": a dependency custom attribute applied to an advice cannot set its Target property to AspectDependencyTarget.Type. Remove the Target property, or apply the dependency custom attribute to the aspect class.` |

## Cause

The <xref:PostSharp.Aspects.Dependencies.AspectDependencyAttribute.Target> property of a dependency custom attribute chooses what the dependency orders. With <xref:PostSharp.Aspects.Dependencies.AspectDependencyTarget.Default>, the dependency applies to the target of the aspect. With <xref:PostSharp.Aspects.Dependencies.AspectDependencyTarget.Type>, it applies to the effects of a member-level aspect on the declaring type of its target, such as introduced members.

A dependency applied to an aspect class can use both targets. A dependency applied to an advice method orders this advice only, so it can only use <xref:PostSharp.Aspects.Dependencies.AspectDependencyTarget.Default>. When it sets <xref:PostSharp.Aspects.Dependencies.AspectDependencyTarget.Type>, PostSharp reports LA0067 on the advice. `<Level>` is always `type`.

## Resolution

* Remove the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAttribute.Target> property, so that the dependency orders the advice on its target.
* Or, when the dependency must order the effects of the aspect on the declaring type, apply the dependency custom attribute to the aspect class instead of the advice method.
