# LA0116: Location Interception Aspect Applied to a Constant

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to field "<Field>" because it is const.` |

## Cause

A <xref:PostSharp.Aspects.LocationInterceptionAspect> intercepts the reads and writes of a field or a property. The compiler replaces every use of a `const` field with its value, so the program never reads the field, and there is nothing to intercept. PostSharp reports the LA0116 warning and does not apply the aspect to the field. The rest of the program is woven normally.

Attribute multicasting skips constants, because <xref:PostSharp.Aspects.LocationInterceptionAspect> accepts non-literal fields only. The message comes from an <xref:PostSharp.Aspects.IAspectProvider> that provides the aspect to every field of a type, constants included. It points to the declaration where the providing aspect is applied.

## Resolution

Skip the constants in the `ProvideAspects` method of the aspect provider: test the <xref:System.Reflection.FieldInfo.IsLiteral> property of each field. If the value of the constant must be intercepted, make it a `static readonly` field or a property.
