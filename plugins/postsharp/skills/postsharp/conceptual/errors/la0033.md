# LA0033: Aspect Provided to an Unknown Declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Error when applying the aspect "<Aspect>": Cannot find the declaration "<Declaration>" in the current assembly or in the assemblies that it references.` |

## Cause

An aspect that implements <xref:PostSharp.Aspects.IAspectProvider> adds aspects to other declarations by returning <xref:PostSharp.Aspects.AspectInstance> objects from its <xref:PostSharp.Aspects.IAspectProvider.ProvideAspects*> method. The target element of each <xref:PostSharp.Aspects.AspectInstance> is a reflection object, which PostSharp maps back to a declaration of the code that it compiles. When the target element is a type, a method or a field that PostSharp cannot find in the current assembly or in the assemblies that the project references, it reports LA0033 on the aspect provider class.

This happens when the reflection object does not describe the code that you compile, but an implementation detail of the .NET runtime that no reference assembly exposes. The most common mistake is to call `GetType()` on the target element: the target element of a type-level aspect is already a <xref:System.Type>, so `GetType()` returns `System.RuntimeType`, the internal class of reflection objects.

## Resolution

Use the target element itself: cast it to <xref:System.Type> in a type-level aspect, or to <xref:System.Reflection.MethodBase> in a method-level aspect, instead of calling `GetType()`. Provide aspects only to declarations of the current assembly, which are the only ones that PostSharp can transform.
