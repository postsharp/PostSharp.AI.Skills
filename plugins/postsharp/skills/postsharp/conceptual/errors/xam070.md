# XAM070: Command Property Is Static or Not of Type ICommand

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Xaml |
| **Message** | `Error in the [Command] aspect applied to property <Property>: only instance properties of type System.Windows.Input.ICommand are supported.` |

## Cause

The <xref:PostSharp.Patterns.Xaml.CommandAttribute> aspect initializes its property with a command object that calls the `Execute` and `CanExecute` members of the instance of the class. PostSharp reports XAM070 when the property cannot hold this object:

* The property is static, so there is no instance whose members the command could call.
* The type of the property is not exactly <xref:System.Windows.Input.ICommand>. A class or another interface that implements <xref:System.Windows.Input.ICommand> is not supported either.

The aspect does not check the visibility of the property, although the current version of the message says that the property must be public. PostSharp reports the message on the property.

## Resolution

Declare the command as an instance property of type <xref:System.Windows.Input.ICommand>, usually with a public getter and a private setter, which the aspect sets. When several objects must share a command, keep the command property in each instance and move the shared logic into the method that the command executes.
