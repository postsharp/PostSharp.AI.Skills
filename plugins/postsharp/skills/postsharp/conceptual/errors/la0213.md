# LA0213: Bound Advice Parameter Passed by Reference

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" cannot be passed by reference because it is bound by <Binding>.` |

## Cause

Each binding attribute of an advice parameter accepts some parameter modes, which can depend on the advice. Many bindings give a value that the advice reads but cannot replace, so they accept only parameters passed by value: for example <xref:PostSharp.Aspects.Advices.ArgumentsAttribute>, <xref:PostSharp.Aspects.Advices.BindingAttribute>, <xref:PostSharp.Aspects.Advices.DeclarationAttribute> and <xref:PostSharp.Aspects.Advices.DeclarationNameAttribute>. PostSharp reports LA0213 when a parameter with such a binding is declared as `in`, `ref` or `out`. `<Binding>` is the binding attribute, such as `[Arguments]`.

When the binding requires a parameter passed by reference, or accepts only `out` and `ref`, and the parameter is passed by value or as `in`, PostSharp reports <xref:la0212?text=LA0212> instead.

In the following example, the interception advice receives the <xref:PostSharp.Aspects.Arguments> object as a `ref` parameter, to change the arguments before it calls the intercepted method. Because the parameter is passed by reference, PostSharp reports the message without a file and line, but the message names the parameter and the advice.

## Resolution

Remove the `in`, `ref` or `out` modifier from the parameter. To change a value that the binding gives by value, change the object itself: <xref:PostSharp.Aspects.Arguments> is a class, so the advice can set its items, and the intercepted method receives the changed arguments when the advice passes the object to the binding. The table of [Binding attributes](xref:advice-parameter-binding#binding-attributes) lists the modes that each attribute accepts.
