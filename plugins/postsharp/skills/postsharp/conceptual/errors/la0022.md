# LA0022: Aspect Serializer Without a Public Parameterless Constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The type "<SerializerType>" cannot be used as the serializer of the aspect "<Aspect>" because it has no public parameterless constructor.` |

## Cause

PostSharp serializes the aspect instances at build time and deserializes them at run time, as <xref:aspect-serialization> describes. You can choose the serializer of an aspect with the `SerializerType` property of an aspect configuration attribute, such as <xref:PostSharp.Aspects.Configuration.OnMethodBoundaryAspectConfigurationAttribute> or <xref:PostSharp.Aspects.Configuration.AspectConfigurationAttribute>, or with the <xref:PostSharp.Aspects.Aspect.SerializerType> property of the aspect. The type must be derived from <xref:PostSharp.Aspects.Serialization.AspectSerializer>.

PostSharp creates the serializer itself, at build time to serialize the aspects and at run time to deserialize them, so the type must have a public constructor without parameters. PostSharp reports LA0022 when it has none: each of its constructors has parameters or is not public. `<SerializerType>` is the configured type, and `<Aspect>` the aspect class. PostSharp reports the message on the serializer class.

PostSharp then also reports <xref:la0001?text=LA0001>, with the message `Object reference not set to an instance of an object`, because it tries to serialize the aspects without a serializer.

## Resolution

* Add a public parameterless constructor to the serializer class. Initialize in this constructor the settings that the other constructors receive, or read them from the aspects themselves.
* Unless the aspect needs a serializer of its own, remove the `SerializerType` property and annotate the aspect class with <xref:PostSharp.Serialization.PSerializableAttribute>.
