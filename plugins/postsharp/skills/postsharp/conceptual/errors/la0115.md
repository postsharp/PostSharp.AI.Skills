# LA0115: Assembly-Level Aspect Dependency Without a Target Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The aspect dependency "<Dependency>" applied to the assembly does not set the TargetType property. At assembly level, set TargetType to the aspect type to which the dependency applies.` |

## Cause

An aspect dependency, such as <xref:PostSharp.Aspects.Dependencies.AspectTypeDependencyAttribute> or <xref:PostSharp.Aspects.Dependencies.AspectRoleDependencyAttribute>, usually decorates an aspect class, and it then applies to that aspect. You can also apply it to the assembly, to order or constrain aspects whose classes you cannot modify. At assembly level, there is no aspect class to attach the dependency to, so the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAttribute.TargetType> property must name it. When this property is not set, PostSharp reports LA0115 and ignores the dependency.

The message does not point to a line, and `<Dependency>` is the kind of dependency (`AspectDependency`), not the name of the custom attribute: look for the aspect dependency attributes applied with `[assembly: ...]` in the project.

## Resolution

Set the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAttribute.TargetType> property of the custom attribute to the aspect type to which the dependency applies. When you can modify the aspect class, you can instead move the custom attribute to that class, where <xref:PostSharp.Aspects.Dependencies.AspectDependencyAttribute.TargetType> is not needed.
