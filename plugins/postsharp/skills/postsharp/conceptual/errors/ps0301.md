# PS0301: License Key Cannot Be Used

| | |
|---|---|
| **Severity** | Warning or Error |
| **Reported by** | PostSharp |
| **Message** | `<Reason>` |

## Cause

Before it builds a project, PostSharp reads every license key that the project and the machine supply: the `PostSharpLicense` MSBuild property or environment variable, the `License` elements of the `postsharp.config` files, and the license keys registered on the machine. PostSharp reports PS0301 for each license key that it rejects, with the reason in the message. `<Reason>` is a complete sentence that names where the key was set, for example the path of a `postsharp.config` file or the `PostSharpLicense` property, rather than quoting the key, which is a secret on a build server.

PostSharp rejects a license key in the following cases:

* The key cannot be read: it is not a license key, it was truncated when it was copied, its signature does not verify, it is not valid yet, or it contains fields that this version of PostSharp does not understand.
* The key is limited to a namespace, and neither the name of the assembly nor the name of the Git repository of the project is in this namespace.
* The key licenses another family of products.
* The license string contains an instruction that PostSharp no longer accepts, or that is reserved for the builds of the source code of PostSharp, or an entry that names a license source without a key.

For a rejected license key, PS0301 is usually a warning: PostSharp ignores the key and builds the project with the other license keys, and reports <xref:ps0242?text=PS0242> when none of them covers the project. For an entry of a license string that PostSharp cannot interpret, such as a retired instruction, PS0301 is an error.

## Resolution

* When the key is malformed or truncated, copy the license key again, in full. See <xref:deploying-keys> for the places where you can set it.
* When the key is limited to a namespace, make sure that the name of the assembly, or the name of the Git repository of the project as it appears in the URL of a remote, starts with the licensed namespace. See <xref:license-troubleshooting>.
* When the key licenses another product, or was generated for a later version of PostSharp, use a key that licenses this version of PostSharp, or upgrade PostSharp.
* When the license string contains an instruction that is no longer supported, remove it.
* When the key is not needed, because another key licenses the project, remove it from the property, the file or the registration where the message says it is set.

To see which keys PostSharp considers and why it rejects them, capture the licensing trace with the `PostSharpTrace` MSBuild property, as <xref:license-troubleshooting> describes.
