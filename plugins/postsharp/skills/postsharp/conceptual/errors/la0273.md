# LA0273: Several Fields Match an Unnamed Field Request

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The aspect "<Aspect>" applied to "<Target>" attempts to introduce a field of type "<FieldType>" in "<TargetType>" without a name, and several existing fields of this type could be used instead: <Fields>. Give the IntroduceFieldAdviceInstance a name, or set its WhenCompatibleFieldExists property to IntroduceAnother to introduce a new field.` |

## Cause

An aspect attempts to introduce a field in its target type by returning an <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance>. When the request has no <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance.Name>, PostSharp recognizes an existing field by its type and its static or instance kind only, among the fields of the target type and the accessible fields of its base types. When several fields match, PostSharp cannot choose one and reports LA0273.

This happens whatever the <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance.WhenCompatibleFieldExists> property of the request, except <xref:PostSharp.Aspects.Advices.IntroduceFieldCompatibleAction.IntroduceAnother>, which introduces a new field without choosing among the existing ones. When exactly one field matches and <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance.WhenCompatibleFieldExists> is <xref:PostSharp.Aspects.Advices.IntroduceFieldCompatibleAction.Fail>, PostSharp reports <xref:la0271?text=LA0271> instead. LA0273 is always an error.

`<Target>` is the declaration to which the aspect is applied, where the error is located, and `<Fields>` lists the matching fields.

## Resolution

* To use one of the existing fields, set the <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance.Name> of the request to the name of this field, with <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance.WhenCompatibleFieldExists> set to <xref:PostSharp.Aspects.Advices.IntroduceFieldCompatibleAction.Ignore>.
* To give the aspect a field of its own, set <xref:PostSharp.Aspects.Advices.IntroduceFieldAdviceInstance.WhenCompatibleFieldExists> to <xref:PostSharp.Aspects.Advices.IntroduceFieldCompatibleAction.IntroduceAnother>. The new field gets a generated name. An advice that imports this field by its type with <xref:PostSharp.Aspects.Advices.ImportMemberAttribute> receives it, because the fields that the aspect requested win over the other fields of the type.
