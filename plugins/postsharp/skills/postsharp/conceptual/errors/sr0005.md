# SR0005: PSerializable Type Already Has a Deserializing Constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply [PSerializable] to type '<Type>' because it already contains a deserializing constructor, which takes a single parameter of type PortableFormatterConstructorContext. Remove this constructor, because PostSharp generates it.` |

## Cause

[<xref:PostSharp.Serialization.PSerializableAttribute>] generates a deserializing constructor in `<Type>`, which <xref:PostSharp.Serialization.PortableFormatter> calls to create the instance before it restores its fields. This constructor has a single parameter of type `PortableFormatterConstructorContext`. PostSharp reports SR0005 when `<Type>` already defines a constructor with this signature, whatever its visibility, because the generated constructor would conflict with it.

This usually happens when you write the deserializing constructor yourself, for example to initialize the fields that are not serialized.

## Resolution

Remove the constructor that takes a `PortableFormatterConstructorContext`. To initialize the fields that are not serialized, implement <xref:PostSharp.Serialization.ISerializationCallback>: <xref:PostSharp.Serialization.PortableFormatter> calls its <xref:PostSharp.Serialization.ISerializationCallback.OnDeserialized> method after it has restored the fields of the object.
