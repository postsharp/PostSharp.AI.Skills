# DOM022: Child Field of a Recordable Class Is Not Recordable

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Model |
| **Message** | `The type of field <Field> is not compatible with the [Recordable] aspect: type <FieldType> does not implement the IRecordable interface and does not have the [Recordable] aspect.` |

## Cause

> [!NOTE]
> Undo/redo, and the <xref:PostSharp.Patterns.Recording.RecordableAttribute> aspect, are deprecated since PostSharp 2026.0.

The <xref:PostSharp.Patterns.Recording.RecordableAttribute> aspect records the changes of an object and of its children, the fields and properties marked with <xref:PostSharp.Patterns.Model.ChildAttribute>, so that an undo reverts a change of a child together with the changes of its parent. A child can take part in the recording only when it is recordable itself.

PostSharp reports DOM022 on a child field of a reference type that implements neither <xref:PostSharp.Patterns.Recording.IRecordable> nor `IDynamicallyAdvisable`, when no <xref:PostSharp.Patterns.Recording.RecordableAttribute> aspect is applied to this type once PostSharp has discovered all the aspects of the project. Fields of an interface type and of type `object` are not checked, because the object that they hold at run time can be recordable. When the type of the child field is a standard collection, PostSharp reports <xref:com008?text=COM008> instead.

## Resolution

* Add the <xref:PostSharp.Patterns.Recording.RecordableAttribute> aspect to the type of the child field.
* When the type cannot have the aspect, because it belongs to another library, exclude the field from the recording with <xref:PostSharp.Patterns.Recording.NotRecordedAttribute>, or remove <xref:PostSharp.Patterns.Model.ChildAttribute> and make the field a reference with <xref:PostSharp.Patterns.Model.ReferenceAttribute>.
