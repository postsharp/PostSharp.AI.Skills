# THR043: AppliesToMethodOnly Argument Has No Effect on a Property

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `The appliesToMethodOnly argument of the [ExplicitlySynchronized] attribute applied to property "<Property>" has no effect: <Reason>. Removing the argument does not change the behavior.` |

## Cause

On a method, the `appliesToMethodOnly` argument of <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute> chooses between two behaviors: with `true`, the threading model adds no code to the method; with `false`, the default, the method runs with the verification of field accesses disabled. See <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute.AppliesToMethodOnly>.

On a property, the threading models ignore the argument, and the behavior depends only on the kind of property:

* The accessors of an automatic property are not enhanced, as with `true`.
* The accessors of a property that is not automatic run with verification disabled, as with `false`.

When the threading model of a class analyzes its properties, it reports THR043 for each property whose attribute receives the argument that requests the other behavior: `true` on a property that is not automatic, or `false` on an automatic property. `<Reason>` states the behavior that the property gets. Only an attribute applied to the property itself is reported, not one that reaches it by multicasting from the class.

## Resolution

* Remove the argument: the behavior of the property does not change.
* When the accessors of a property that is not automatic must not be enhanced at all, replace the property with methods, where the argument applies.
