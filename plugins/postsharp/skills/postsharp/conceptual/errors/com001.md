# COM001: Field or Property Has Several Relationship Attributes

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Common |
| **Message** | `<Member> cannot have more than one custom attribute of type [Child], [Reference] or [Parent].` |

## Cause

The <xref:PostSharp.Patterns.Model.AggregatableAttribute> aspect builds the parent/child graph of your objects from the relationship attribute of each field and automatic property of the class: <xref:PostSharp.Patterns.Model.ChildAttribute> when the object belongs to the instance, <xref:PostSharp.Patterns.Model.ReferenceAttribute> when it is only referred to, and <xref:PostSharp.Patterns.Model.ParentAttribute> when it is the parent of the instance. These relationships exclude each other, so PostSharp reports COM001 when a field or an automatic property has more than one of them.

When the `PostSharpUnifiedAutomaticPropertyAnnotations` MSBuild property is `True`, PostSharp reads the attributes of an automatic property and of its backing field (`[field: Child]`) as one set, so a different attribute on each of them also reports COM001.

## Resolution

Keep the one attribute that describes the relationship:

* <xref:PostSharp.Patterns.Model.ChildAttribute> when the instance owns the object, which then gets the instance as its parent.
* <xref:PostSharp.Patterns.Model.ReferenceAttribute> when the object belongs to another part of the graph or is shared.
* <xref:PostSharp.Patterns.Model.ParentAttribute> when the field or property receives the parent of the instance.
