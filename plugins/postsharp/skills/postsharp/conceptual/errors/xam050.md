# XAM050: Dependency Property Declared in a Type That Is Not a DependencyObject

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Xaml |
| **Message** | `[<Aspect>] cannot be applied to property <Property>: the declaring type <DeclaringType> does not derive from the DependencyObject class.` |

## Cause

The <xref:PostSharp.Patterns.Xaml.DependencyPropertyAttribute> aspect registers its target property with the WPF property system, which stores the value of a dependency property in the object that owns it. Only a <xref:System.Windows.DependencyObject> can store such values, so the class that declares the property must derive from <xref:System.Windows.DependencyObject>. The <xref:PostSharp.Patterns.Xaml.AttachedPropertyAttribute> aspect has the same requirement for the class that declares the attached property.

PostSharp reports XAM050 on the property when its declaring class does not derive from <xref:System.Windows.DependencyObject>, directly or through a base class such as `FrameworkElement`. `<Aspect>` is `DependencyProperty` or `AttachedProperty`.

## Resolution

Derive the declaring class from <xref:System.Windows.DependencyObject>, or from a WPF class that derives from it, such as `UIElement`, `FrameworkElement` or `Control`. When the class cannot derive from <xref:System.Windows.DependencyObject>, use a plain property instead, and add the <xref:PostSharp.Patterns.Model.NotifyPropertyChangedAttribute> aspect to the class if a binding must observe its changes.
