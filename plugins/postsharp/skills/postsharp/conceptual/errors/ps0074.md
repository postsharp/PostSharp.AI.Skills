# PS0074: Signing Requested for an Assembly Without a Public Key

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The assembly has no public key, so PostSharp does not sign it although the SignAssembly property is true. Sign the assembly in the project, or set the SignAssembly property to false.` |

## Cause

PostSharp rewrites the assembly that the C# or Visual Basic compiler produced. When this assembly is signed, PostSharp signs the woven assembly again with the same key, without any setting: it reads the key file of the project and the strong-name attributes of the assembly.

The `SignAssembly` property of the PostSharp compiler forces signing. `PostSharp.targets` sets it from the `PostSharpSignAssembly` MSBuild property, and you can also set it in the `PostSharpProperties` MSBuild property. PostSharp can only sign an assembly that has a public key in its manifest. When `SignAssembly` is true but the assembly that the compiler produced has no public key, because the project itself is not signed, PostSharp reports PS0074 and writes the woven assembly without a strong name.

## Resolution

* When the assembly must be signed, sign it in the project, with the `SignAssembly` and `AssemblyOriginatorKeyFile` MSBuild properties. PostSharp then signs the woven assembly with the same key, and you do not need the `PostSharpSignAssembly` property.
* When the assembly does not need a strong name, remove the `PostSharpSignAssembly` property, or the `SignAssembly` entry of the `PostSharpProperties` property.
