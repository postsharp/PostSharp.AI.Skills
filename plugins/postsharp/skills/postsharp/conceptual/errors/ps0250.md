# PS0250: Property Element Has Attributes in a Configuration File

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The element "<ParentElement>/<PropertyElement>" cannot have attributes, because it sets the member "<PropertyElement>" of "<ParentElement>". Set the attributes on the elements that it contains.` |

## Cause

Some sections of a `postsharp.config` file, such as the `Logging` element, describe objects in XML. In these sections, an element represents an object, its attributes set the simple properties of the object, and a child element named after a property sets a property whose value is an object or a collection. The value of this property element is the element, or the elements, that it contains. For example, the `DefaultOptions` element of a `LoggingProfile` contains one `LoggingOptions` element, and the `Profiles` element of `Logging` contains `LoggingProfile` elements.

A property element cannot have attributes, because PostSharp does not create an object for it. PostSharp reports PS0250 on the first attribute of the property element, where `<ParentElement>` is the object element and `<PropertyElement>` is the property element. The message is an error, but PostSharp goes on reading the file to report the other mistakes it finds.

## Resolution

Move the attributes to the element that the property element contains: for `DefaultOptions` and `ExceptionOptions`, to their `LoggingOptions` element; for `Profiles`, to a `LoggingProfile` element. When the attribute is a property of the parent object, such as `IncludeExecutionTime` of a `LoggingProfile`, move it to the parent element. <xref:configuration-schema> shows where each attribute goes.
