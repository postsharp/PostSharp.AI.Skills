# LA0014: Aspect Constructor or Property Setter Threw an Exception

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `<ExceptionMessage>` |

## Cause

PostSharp creates the aspect instances at build time: for each custom attribute that is an aspect, it calls the constructor of the aspect class with the arguments of the attribute, then the setters of the properties that the attribute names. When the constructor or a setter throws an exception, PostSharp cannot create the aspect and reports LA0014.

`<ExceptionMessage>` names the aspect class, the constructor or the property setter that failed, and the exception with its message. When the constructor failed because an assembly could not be loaded, the message also describes the failed binding.

PostSharp reports the message on the aspect class, not on the declaration to which the aspect is applied. When the aspect is applied in several places, look for the usages that pass the value that the exception message rejects.

## Resolution

* Pass arguments that the constructor and the setters of the aspect accept.
* When the check of the aspect is meant to report a usage error, move it from the constructor or the setter to <xref:PostSharp.Aspects.MethodLevelAspect.CompileTimeValidate*>, and report a message with <xref:PostSharp.Extensibility.Message.Write*>: the message then has the location of the declaration to which the aspect is applied.
