# LA0151: Binding Attribute Not Accepted in This Advice

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Unexpected <Binding> parameter in the advice "<Advice>". The <Binding> parameter can be used only in these advices: <EligibleAdvices>.` |

## Cause

Each binding attribute of an advice parameter gives a value that exists only in some kinds of advices. For instance, the exception thrown by the target method, which <xref:PostSharp.Aspects.Advices.ExceptionAttribute> binds, exists only in an <xref:PostSharp.Aspects.Advices.OnMethodExceptionAdvice>, and the awaited task of <xref:PostSharp.Aspects.Advices.AwaitedTaskAttribute> only in an <xref:PostSharp.Aspects.Advices.OnMethodYieldAdvice>. When a parameter has a binding attribute that the kind of its advice does not accept, and PostSharp cannot emit the value there, it reports LA0151 on the parameter.

`<Binding>` is the binding attribute as you write it, such as `[Exception]`, and `<EligibleAdvices>` lists the advice attributes that accept it. The table in [Bindings by advice kind](xref:advice-parameter-binding#bindings-by-advice-kind) shows the binding attributes that each advice accepts. Some combinations report another message instead: <xref:la0224?text=LA0224> in an <xref:PostSharp.Aspects.Advices.OnInstanceConstructedAdvice>, and the warning <xref:la0233?text=LA0233> for `[Arguments]` and `[FlowBehavior]`, which build but whose value is ignored.

## Resolution

* Move the parameter to an advice of a kind listed in the message. For the exception, use an <xref:PostSharp.Aspects.Advices.OnMethodExceptionAdvice>, which runs only when the target method throws.
* Otherwise, remove the parameter.
