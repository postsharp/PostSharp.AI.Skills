# PS0138: Required Expression Evaluates to an Empty String

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Expression "<Expression>" cannot evaluate to an empty value.` |

## Cause

Many attributes of a `postsharp.config` file accept expressions, such as `{$ExtraPlugIn}`, which PostSharp evaluates when it loads the file. See <xref:configuration-xpath>. A property that is not defined evaluates to an empty string, without an error.

Some attributes cannot be empty, because PostSharp cannot do anything with an empty value. PostSharp reports PS0138 when one of them evaluates to an empty string, or to a string of white space:

* The `File` attribute of a `Using` element, which names the plug-in or the configuration file to import.
* The `TypeName` attribute of a `Service` element.
* The PostSharp properties that give the output file of the build and the file that lists the installed frameworks. The MSBuild targets of PostSharp set them, so an empty value means that the build was customized.

`<Expression>` is the expression as written, before evaluation. The location of the message is the element of the configuration file. Because the configuration of the project has an error, PostSharp then stops with <xref:ps0084?text=PS0084>.

## Resolution

* Set the property that the expression refers to, in the `postsharp.config` file with a `Property` element, or from MSBuild with the `PostSharpProperties` property. See <xref:configuration-postsharp>.
* When the element is needed only when the property is set, add a `Condition` attribute to it, as in `Condition="{$ExtraPlugIn != ''}"`. PostSharp evaluates the condition first and skips the element when it is false.
* Check the spelling of the property name: a misspelled property evaluates to an empty string.
