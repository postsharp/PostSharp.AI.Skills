# LA0278: Constructor With Dependencies Clashes With Another Constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The constructor "<Constructor>" of "<Type>" cannot receive the dependencies <Dependencies>: the constructor with the added parameters would have the signature of the constructor "<OtherConstructor>". Remove one of the two constructors.` |

## Cause

When an aspect attempts to introduce a dependency with <xref:PostSharp.Aspects.Advices.ImportDependencyAdviceInstance>, and the class has no field or readable instance property of the service type, PostSharp transforms each instance constructor of the class and of its derived classes. A constructor that has no parameter of exactly the service type gets an *enhanced constructor*: its own parameters followed by one parameter for each missing dependency. The original constructor becomes a forwarder that calls it.

PostSharp reports LA0278 on `<Constructor>` when its enhanced constructor would have the parameter types of `<OtherConstructor>`, which the class already declares. `<Dependencies>` lists the types of the parameters that PostSharp would add. A typical case is a parameterless constructor next to a constructor that receives the service.

## Resolution

Remove one of the two constructors. Usually, remove the constructor that does not receive the service: the constructor that does receives the dependency of the aspect from its own parameter, and PostSharp does not change it. A container passes the service, and code that uses `new` passes it explicitly.

Declaring the missing parameters in `<Constructor>` does not help, because the constructor then has the parameter types of `<OtherConstructor>`, which C# rejects.
