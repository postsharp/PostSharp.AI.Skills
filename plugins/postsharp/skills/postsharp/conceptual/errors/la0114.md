# LA0114: Method Interception Aspect Applied to a Static Constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to the static constructor of type "<Type>": a method interception aspect cannot be applied to a static constructor.` |

## Cause

A <xref:PostSharp.Aspects.MethodInterceptionAspect> replaces the body of its target method with a call to <xref:PostSharp.Aspects.MethodInterceptionAspect.OnInvoke*>. PostSharp does not support this transformation on a static constructor, which the runtime calls itself, and reports LA0114 instead of weaving the aspect.

Attribute multicasting never applies a <xref:PostSharp.Aspects.MethodInterceptionAspect> to a static constructor, because the aspect does not accept this kind of target. The message comes from code that chooses the targets itself: an <xref:PostSharp.Aspects.IAspectProvider> that provides the aspect to the type initializer, or an <xref:PostSharp.Aspects.Advices.OnMethodInvokeAdvice> whose pointcut selects a static constructor.

`<Type>` is the type that declares the static constructor. The message points to the declaration where the providing aspect is applied.

## Resolution

Provide the aspect to methods only: in the `ProvideAspects` method of the aspect provider, skip the type initializer and the other constructors. To run code when a type is initialized, call it from the static constructor itself.
