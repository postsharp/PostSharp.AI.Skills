# AR0102: Component-Internal Declaration Used Outside of Its Component

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `<ReferencedKind> <ReferencedDeclaration> cannot be referenced from <ReferencingKind> <ReferencingDeclaration> because of the [ComponentInternal] constraint.` |

## Cause

The <xref:PostSharp.Constraints.ComponentInternalAttribute> constraint restricts the use of a declaration to a component, a visibility between `internal` and `private`. With the default constructor, the component is the namespace of the type that declares the declaration. The other constructors take a list of friend types or namespaces instead; a friend namespace includes its child namespaces. Code in the same top-level type as the declaration always has access.

PostSharp reports AR0102 on each method or type that references the declaration from outside of the component: it calls the method, reads the field, derives from the type, or uses the type in a signature. `<ReferencingDeclaration>` is the method or type that holds the reference, and the message is reported at its location, not at the line of the reference.

AR0102 is a warning by default. Its severity comes from the <xref:PostSharp.Constraints.ComponentInternalAttribute.Severity> property of the constraint, which you can set to <xref:PostSharp.Extensibility.SeverityType.Error>.

## Resolution

* Go through the public API of the component, which is allowed to use the declaration, instead of using the declaration directly.
* When the referencing type belongs to the component, add it, or its namespace, to the friend types or namespaces of the constraint.
* When the reference is an exception that you accept, suppress the warning on the referencing declaration with <xref:PostSharp.Extensibility.SuppressWarningAttribute>. This does not work when the severity of the constraint is <xref:PostSharp.Extensibility.SeverityType.Error>.
