# LA0220: Type Argument of a Generic Advice Cannot Be Inferred

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The type argument "<TypeParameter>" of the advice "<Advice>" cannot be inferred for "<Target>": <Reason>.` |

## Cause

An advice method can be generic. For each target, PostSharp infers its type arguments from the values that the parameters bind, such as the arguments bound by <xref:PostSharp.Aspects.Advices.ArgumentAttribute>, with rules similar to the type inference of C#, and then checks the constraints of the type parameters. When it cannot find a type argument for a target, it reports LA0220 on the target. `<Reason>` says why:

* The constraint is not satisfied: for example, the type argument is not a reference type, not a non-nullable value type, has no public parameterless constructor, is not an unmanaged type, or does not derive from or implement the type of a constraint.
* Two bound values of a type parameter have types with no common type, such as `int` and `string`.
* Two `ref`, `out` or `in` parameters of one type parameter bind locations of different types, so the type argument would have to be both.

A violated constraint is reported even when the advice uses the <xref:PostSharp.Aspects.Advices.MatchPointcut> pointcut, because the target has the signature of the advice. Conflicting types, on the contrary, make <xref:PostSharp.Aspects.Advices.MatchPointcut> skip the target.

## Resolution

* Apply the aspect only to targets whose bound values fit the type parameters and their constraints.
* Relax the constraint of the type parameter, or bind another value, for example another argument.
* In a type-level aspect, write one advice per kind of target and select them with the <xref:PostSharp.Aspects.Advices.MatchPointcut> pointcut, when the targets differ by their signature.
