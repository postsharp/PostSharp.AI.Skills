# LA0164: Method Interception Applied to a Method That Returns by Reference

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to method "<Method>": applying this aspect to a method returning a managed pointer (ref return) is not supported.` |

## Cause

Method interception replaces the body of the target method with a call to the `OnInvoke` advice, which receives the return value of the method as an object in <xref:PostSharp.Aspects.MethodInterceptionArgs.ReturnValue>. A method declared with `ref` or `ref readonly` before its return type returns a reference to a variable, not a value, and this reference cannot be stored as an object. PostSharp therefore reports LA0164 when one of the following is applied to such a method:

* an aspect derived from <xref:PostSharp.Aspects.MethodInterceptionAspect>;
* an aspect with an advice method marked with <xref:PostSharp.Aspects.Advices.OnMethodInvokeAdvice>.

A method that returns by reference usually receives the aspect through multicasting, when the aspect is applied to its class or assembly.

In the following example, the `[Log]` aspect is multicast to the methods of `Inventory`, including `GetQuantity`, which returns a reference to an element of an array. PostSharp reports the error on the class that carries the multicast attribute, and names the method in the message.

## Resolution

* Exclude the method from the multicast, with a custom attribute of the aspect that sets <xref:PostSharp.Extensibility.MulticastAttribute.AttributeExclude> to `true` on the method.
* Restrict the multicast with a filter such as <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetMembers>, so that it does not match the method.
* If the method does not need to return a reference, make it return the value.
