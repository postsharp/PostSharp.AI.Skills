# PS0065: Attribute That Allows a Single Instance Is Declared Several Times

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Multiple instances of the custom attribute "<Attribute>" are declared on "<Declaration>", but the attribute has MulticastAttributeUsage.AllowMultiple = false.` |

## Cause

The <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute.AllowMultiple> property of the <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute> of an aspect class says whether a declaration can receive several instances of the aspect. When it is `false`, and an instance multicast from a container, such as a class or the assembly, reaches a declaration that already has one, the new instance overrides the previous one: see <xref:multicast-override>.

PostSharp cannot choose between two instances that are declared directly on the same declaration, so it reports PS0065. This check is distinct from the `AllowMultiple` property of the <xref:System.AttributeUsageAttribute> of C#: the base aspect classes of PostSharp, such as <xref:PostSharp.Aspects.OnMethodBoundaryAspect>, allow several instances for C#, so the C# compiler accepts the duplicate attributes and only PostSharp rejects them.

PostSharp reports the message on the declaration that has the attributes. `<Attribute>` is the full name of the attribute class.

## Resolution

* Remove the extra instances, so that the declaration has a single instance of the attribute.
* When the attribute is designed to be applied several times to the same declaration, set <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute.AllowMultiple> to `true` in the `[MulticastAttributeUsage]` of the attribute class, or remove the property. PostSharp then applies every instance. A base class that sets `AllowMultiple` to `false` cannot be overridden this way: PostSharp reports <xref:ps0072?text=PS0072>.
