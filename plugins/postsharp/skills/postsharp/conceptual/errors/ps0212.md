# PS0212: Intercepted Field Passed by Reference from Another Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The field "<Field>" cannot be loaded by reference in method "<Method>" because an aspect is applied to it. To pass the field by reference or call a method of the field, copy it to a local variable, use the local variable, and assign the local variable back to the field.` |

## Cause

When an aspect such as a <xref:PostSharp.Aspects.LocationInterceptionAspect> is applied to a field, PostSharp turns the field into a property of the same name, renames the field and makes it private, and replaces every read and write of the field in the project with a call to the property. See <xref:location-interception>.

Code that loads the address of the field cannot be redirected to a property: passing the field as a `ref` or `out` argument, or calling a method of a field of a structure type. When this code is in the type that declares the field, PostSharp reports the warning <xref:ps0089?text=PS0089> and the access bypasses the aspect. When it is in another type, the private field is no longer accessible, so PostSharp reports PS0212 at the location of the access.

## Resolution

Do not load the address of the field. Pass a local variable by reference instead, and assign it to the field afterwards: the assignment goes through the aspect. To call a method of a field of a structure type, copy the field to a local variable, call the method on the local variable, and assign it back to the field.

Making the field private does not help, since the other type then cannot access it at all, and a property cannot be passed by reference in C#.
