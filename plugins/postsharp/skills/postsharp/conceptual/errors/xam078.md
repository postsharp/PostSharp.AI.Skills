# XAM078: Invalid Signature of the CanExecute Method of a Command

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Xaml |
| **Message** | `Error in the [Command] aspect applied to property <CommandProperty>: the signature of method <CanExecuteMethod> is incorrect. The CanExecute method must be a non-static method that returns bool and has zero or one parameter, for example "bool MyCanExecute()" or "bool MyCanExecute(ParamType)".` |

## Cause

The <xref:PostSharp.Patterns.Xaml.CommandAttribute> aspect implements the <xref:System.Windows.Input.ICommand.CanExecute(System.Object)> method of the command by calling a method of the view model. It looks for a method named `CanExecute<Name>` or `Can<Name>`, where `<Name>` is the name of the command property without the `Command` suffix, or for the method named by the <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteMethod> property of the aspect. When the class declares such a method, a method takes precedence over a `CanExecute` property of the same name.

The aspect reports XAM078 when this method cannot implement `CanExecute`, because it:

* does not return `bool`;
* is static;
* has more than one parameter. The only parameter allowed receives the command parameter.

PostSharp reports the message on the command property, not on the method. In the current version, `<CanExecuteMethod>` shows the name of an internal type of the aspect instead of the name of the method.

## Resolution

Change the signature of the `CanExecute` method: make it an instance method that returns `bool` and has no parameter, or one parameter that receives the command parameter. If the method is not meant to implement `CanExecute`, rename it, or set <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteMethod> to the name of another method.
