# PS0278: Aspect Weaver Plug-In Requires a Framework License

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The custom aspect weaver plug-in "<PlugInType>" requires a PostSharp Framework or PostSharp Ultimate license.` |

## Cause

An aspect weaver plug-in is an extension of the PostSharp compiler, written with the PostSharp SDK, that weaves aspects of its own. Integrating with the aspect weaver is a premium feature, which PostSharp Essentials does not provide at all: a plug-in that is not part of PostSharp requires a license that covers PostSharp Framework, such as a PostSharp Framework or a PostSharp Ultimate license.

When PostSharp loads the aspect weaver plug-ins of the project, it checks the license of each plug-in whose assembly name does not start with `PostSharp.`. When no license of the build covers PostSharp Framework, PostSharp reports PS0278, where `<PlugInType>` is the full name of the type of the plug-in, and does not use the plug-in. Before PS0278, PostSharp reports the message of the licensing services, which names the products that cover PostSharp Framework: <xref:ps0127?text=PS0127>, or <xref:ps0242?text=PS0242> when PostSharp found no license at all.

This message depends on the license of the build and on a plug-in of the PostSharp SDK, so no example can show it.

## Resolution

* Register a PostSharp Framework or PostSharp Ultimate license key for the project. See <xref:deploying-keys>.
* When the project does not need the plug-in, remove the reference to the package or the add-in that provides it.
* When you expected your license to cover the plug-in, check that PostSharp uses it: an expired or rejected key is reported by <xref:ps0301?text=PS0301> or <xref:ps0304?text=PS0304> earlier in the build.
