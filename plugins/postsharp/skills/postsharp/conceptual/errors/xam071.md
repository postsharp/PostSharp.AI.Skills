# XAM071: Command Member Named by the Aspect Does Not Exist

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Xaml |
| **Message** | `Error in the [Command] aspect applied to property <Property>: type <Type> does not contain any <MemberKind> named <Name>.` |

## Cause

By default, the <xref:PostSharp.Patterns.Xaml.CommandAttribute> aspect finds the members of a command by naming conventions: for a `SubmitCommand` property, an `ExecuteSubmit` or `Submit` method, and an optional `CanExecuteSubmit` or `CanSubmit` method or property. When you set the <xref:PostSharp.Patterns.Xaml.CommandAttribute.ExecuteMethod>, <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteMethod> or <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteProperty> property of the aspect, the aspect looks for a member with exactly this name instead, and reports XAM071 when the class does not have one.

`<MemberKind>` is `method` or `property`, depending on the aspect property that you set. The aspect only looks at the members declared in the class of the command property itself: a member that a base class declares is not found either. PostSharp reports the message on the command property.

## Resolution

* Correct the name in the aspect property. Use the `nameof` operator rather than a string literal, so that the C# compiler checks the name and a rename updates it.
* When the member is declared in a base class, declare it in the class of the command property, for example as a method that calls the member of the base class.
* Remove the aspect property and name the members by the conventions of the aspect.
