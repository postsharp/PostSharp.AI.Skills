# LA0175: Method Boundary Advice Cannot Advise the Method Semantically

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the advice "<Advice>" to method "<Method>": OnMethodBoundary semantic advising currently can be applied only to iterator and enumerable methods, async methods and any methods returning Task, Task<T>, IEnumerable, IEnumerable<T>, IEnumerator, or IEnumerator<T> without by-reference parameters. You can suppress this error message by setting the UnsupportedTargetAction property on the master advice.` |

## Cause

This is the counterpart of <xref:la0174?text=LA0174> for aspects made of advices, such as <xref:PostSharp.Aspects.Advices.OnMethodEntryAdvice> and <xref:PostSharp.Aspects.Advices.OnMethodExitAdvice>. By default, a group of method boundary advices advises semantically the methods that return an awaitable type, also when they are not `async`. For such a method, which has no state machine, PostSharp generates one. It can do so only for a method that returns a <xref:System.Threading.Tasks.Task>, a <xref:System.Threading.Tasks.Task`1> or an enumerable type, and has no `ref` or `out` parameter.

PostSharp reports LA0175 on the target method when it should advise the method semantically, cannot generate the state machine, and the <xref:PostSharp.Aspects.Advices.OnMethodBoundaryAdvice.UnsupportedTargetAction> property of the master advice of the group keeps its default value, <xref:PostSharp.Aspects.UnsupportedTargetAction.Fail>. The typical case is a method that returns a <xref:System.Threading.Tasks.ValueTask`1> without the `async` keyword. `<Advice>` is the master advice.

## Resolution

* Make the method return a <xref:System.Threading.Tasks.Task> or a <xref:System.Threading.Tasks.Task`1>, or remove its `ref` and `out` parameters.
* Set the <xref:PostSharp.Aspects.Advices.OnMethodBoundaryAdvice.UnsupportedTargetAction> property of the master advice to <xref:PostSharp.Aspects.UnsupportedTargetAction.Fallback>, so that the advices wrap the method itself, or to <xref:PostSharp.Aspects.UnsupportedTargetAction.Ignore> to skip the method.
* Exclude the method from semantic advising with the <xref:PostSharp.Aspects.Advices.OnMethodBoundaryAdvice.SemanticallyAdvisedMethodKinds> property of the master advice.
