# AR0105: Internal Declaration Used from Another Assembly

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `Cannot use <ReferencedKind> <ReferencedDeclaration> in <ReferencingKind> <ReferencingDeclaration> because the [Internal] constraint restricts it to its own assembly and to the assemblies that this assembly grants access to with [InternalsVisibleTo].` |

## Cause

The <xref:PostSharp.Constraints.InternalAttribute> constraint marks a declaration that must be `public` for technical reasons as an implementation detail of its assembly. When PostSharp processes another assembly, it checks the references of this assembly to the declaration, and reports AR0105 on each method or type that uses it: it calls the method or constructor, reads the field, derives from the type, uses the type in a signature, or applies the custom attribute. A reference is allowed when the assembly of the declaration grants access to the referencing assembly with <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute>.

`<ReferencingDeclaration>` is the declaration that holds the reference, and the message is reported at its location, not at the line of the reference. The check runs only when the referencing project is processed by PostSharp.

AR0105 is a warning by default. Its severity comes from the <xref:PostSharp.Constraints.InternalAttribute.Severity> property of the constraint, which you can set to <xref:PostSharp.Extensibility.SeverityType.Error>.

## Resolution

* Use the public API of the library instead of the internal declaration.
* When the referencing assembly is a trusted part of the same product, such as a test project, add an <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> to the assembly of the declaration.
* When the reference is an exception that you accept, suppress the warning on the referencing declaration with <xref:PostSharp.Extensibility.SuppressWarningAttribute>. This does not work when the severity of the constraint is <xref:PostSharp.Extensibility.SeverityType.Error>.
