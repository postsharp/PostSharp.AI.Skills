# LA0072: Introduced Method Has a Different Visibility than the Existing Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot introduce method "<Method>" into type "<TargetType>" because it is already defined in type "<DeclaringType>" with a visibility different from the Visibility property of the introduction.` |

## Cause

When an aspect introduces a method with <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute> and sets its <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrFail> or <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrIgnore>, PostSharp replaces or overrides the method of the same name and signature that already exists. The introduced method must have the same visibility as the existing one. When they differ, PostSharp reports LA0072, for both override actions.

The visibility of the introduced method is the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.Visibility> property of the introduction, which is <xref:PostSharp.Reflection.Visibility.Public> by default. The visibility of the method in the aspect class does not count.

`<DeclaringType>` is the type that defines the existing method: the target type itself, or one of its base types. For a property or an event, PostSharp checks each accessor, so `<Method>` is the name of the accessor, such as `get_Name`.

## Resolution

* Set the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.Visibility> property of the introduction to the visibility of the existing method, for example <xref:PostSharp.Reflection.Visibility.Family> for a `protected` method.
* Change the visibility of the existing method, when you own it.
