# AR0101: Interface Marked [InternalImplement] Implemented in Another Assembly

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `Interface <Interface> cannot be implemented by <ImplementingType> because of the [InternalImplement] constraint.` |

## Cause

The <xref:PostSharp.Constraints.InternalImplementAttribute> constraint lets other assemblies use a public interface but not implement it, so that its author can add members to it later without breaking their code. When PostSharp processes an assembly that references the interface, it reports AR0101 on each type of this assembly that derives from the interface. A type is allowed when the assembly of the interface grants access to the implementing assembly with <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute>. The check runs only when the implementing project is processed by PostSharp.

AR0101 is a warning by default. Its severity comes from the <xref:PostSharp.Constraints.InternalImplementAttribute.Severity> property of the constraint, which you can set to <xref:PostSharp.Extensibility.SeverityType.Error>.

## Resolution

* Use the implementations that the library of the interface provides, through its factory methods or its public classes, instead of implementing the interface.
* When the implementing assembly is a trusted part of the same product, such as a test project, add an <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> to the assembly of the interface.
* When the implementation is an exception that you accept, suppress the warning on the implementing type with <xref:PostSharp.Extensibility.SuppressWarningAttribute>. Your type then breaks when the library adds a member to the interface. The suppression does not work when the severity of the constraint is <xref:PostSharp.Extensibility.SeverityType.Error>.
