# LA0261: Field Imported by Reference Is Turned into a Property

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is bound by [ImportMember] and passed as out or ref to the field "<Field>", but an aspect turns this field into a property, which has no address. Pass the parameter by value or as in, or import the field as ILocationBinding<T>.` |

## Cause

An advice parameter annotated with <xref:PostSharp.Aspects.Advices.ImportMemberAttribute> and passed as `ref` or `out` receives a reference to a field of the target type, so that the advice can change the field. When another aspect, such as a <xref:PostSharp.Aspects.LocationInterceptionAspect>, turns this field into a property, the order of the two aspects decides what the advice sees. An advice ordered before the other aspect sees the field itself. An advice ordered after it sees the property, whose value goes through the accessors and has no address, so PostSharp cannot pass it by reference and reports LA0261.

PostSharp reports the message on the target of the advice. `<Field>` is the name of the field in the source code.

## Resolution

Choose one of the following:

* Import the field as <xref:PostSharp.Aspects.ILocationBinding`1>, and read and write it on the instance received by a <xref:PostSharp.Aspects.Advices.ThisAttribute> parameter. The values go through the property, so the other aspect sees the changes.
* Pass the parameter by value or as `in`, when the advice only reads the field. The advice receives the value that the property returns.
* Order the aspect before the aspect that turns the field into a property, with <xref:PostSharp.Aspects.Dependencies.AspectTypeDependencyAttribute>. The `ref` parameter then references the field itself, and the changes bypass the other aspect.
