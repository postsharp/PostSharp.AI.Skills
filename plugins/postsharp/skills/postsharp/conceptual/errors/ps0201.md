# PS0201: Type Named in XML Configuration Not Found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot find the type '<TypeName>' that this XML element names. Check the name of the element and the clr-namespace and assembly of its XML namespace.` |

## Cause

Some elements of a `postsharp.config` file contain CLR objects written in XML: the children of the `Multicast` element, which add aspects to the project, and the content of the `Logging` element, which configures the logging profiles. The name of such an element is the name of the class, with or without its `Attribute` suffix, and its XML namespace gives the .NET namespace and the assembly of the class, in the form `clr-namespace:Namespace;assembly:Assembly`. See <xref:configuration-serialization>.

PostSharp reports PS0201 when no class with this name exists in this namespace and assembly. `<TypeName>` is the full name that PostSharp looked for, with the assembly. The location of the message is the XML element. The usual causes are:

* The class was renamed or moved to another namespace, and the configuration file was not updated.
* The name of the element is misspelled.
* The `clr-namespace` or the `assembly` of the XML namespace is wrong, for example the name of the project instead of the name of the assembly, or the assembly is not referenced by the project.

## Resolution

* Make the name of the element the name of the class, with or without its `Attribute` suffix.
* Make the `clr-namespace` of the XML namespace the namespace of the class, and its `assembly` the name of the assembly that declares the class, without extension. When the class is in another assembly, make sure that the project references it.
