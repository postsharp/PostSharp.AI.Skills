# PS0265: Assembly Loading Log

| | |
|---|---|
| **Severity** | Information |
| **Reported by** | PostSharp |
| **Message** | `Assembly loading log for the previous error:\n<Log>` |

## Cause

When PostSharp cannot load an assembly, or cannot bind a type or a member, it reports the error <xref:ps0264?text=PS0264> on one line, with the reason of the failure. It then reports PS0265, an important informational message, whose `<Log>` gives the record of the failure, in sections:

* `Failure`: the type and the message of the exception, when the failure is about an assembly.
* `PostSharp binding log of the current thread`: the steps of PostSharp to resolve the assemblies and the types.
* `Requests of the CLR host assembly store for this assembly in this AppDomain`: the requests for the assembly that reached the assembly store of PostSharp.
* `Last exception caught by the CLR host assembly store on this thread`.
* `Binding log of the runtime`, when the runtime gives one.

PostSharp reports the log of an assembly once, after the first <xref:ps0264?text=PS0264> error about this assembly. The later errors about the same assembly refer to this first PS0265 message instead of repeating it. PS0265 is not an error by itself: the build fails because of <xref:ps0264?text=PS0264>.

When the compiler of PostSharp runs in the pipe server, MSBuild receives the log as one critical message. When it runs as a separate process, each line of the log becomes a message of normal importance, so the log is visible only at the `normal` verbosity of MSBuild or higher.

The test framework of the examples records only warnings and errors, so no example can show this message. The example of <xref:ps0264?text=PS0264> reports it too.

## Resolution

Resolve the <xref:ps0264?text=PS0264> error that PS0265 follows. Use the log to find which assembly, and which version of it, PostSharp could not load, and the exception that the runtime or PostSharp reported; then follow the resolution of <xref:ps0264?text=PS0264>.

When the log does not appear, build with the `normal` or `detailed` verbosity, for example `dotnet build -v:n`. For more details, capture the `AssemblyBinder` trace category with the `PostSharpTrace` MSBuild property, as <xref:msbuild-properties> describes.
