# LA0245: Type Parameter of a Generic Advice Cannot Be Inferred

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The type parameter "<TypeParameter>" of the advice "<Advice>" is not used by any parameter bound by [Argument], [Arguments], [Binding], [ImportMember], [LocationValue], [ReturnValue] or [This], so it cannot be inferred, and its type argument is object.` |

## Cause

An advice method can be generic. For each target, PostSharp infers its type arguments from the types of the values that the parameters receive, as C# infers the type arguments of a method call. Only the parameters bound by [<xref:PostSharp.Aspects.Advices.ArgumentAttribute>], [<xref:PostSharp.Aspects.Advices.ArgumentsAttribute>], [<xref:PostSharp.Aspects.Advices.BindingAttribute>], [<xref:PostSharp.Aspects.Advices.ImportMemberAttribute>], [<xref:PostSharp.Aspects.Advices.LocationValueAttribute>], [<xref:PostSharp.Aspects.Advices.ReturnValueAttribute>] and [<xref:PostSharp.Aspects.Advices.ThisAttribute>] receive a value of the target from which a type argument can be inferred.

PostSharp reports LA0245 for each type parameter `<TypeParameter>` of the advice `<Advice>` that the types of these parameters do not use. Its type argument is then <xref:System.Object> for every target. PostSharp reports the warning once, on the advice method, and not for each target.

## Resolution

* Use the type parameter in the type of a parameter bound by one of these attributes, for instance `[ReturnValue] TResult result`, so that PostSharp infers it for each target.
* Or remove the type parameter, when the advice does not need it.
