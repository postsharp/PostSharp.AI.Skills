# LA0064: Introduced Event Has a Different Type than the Existing Event

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot introduce event "<Event>" into type "<TargetType>" because an event with the same name, but of a different type, is defined in type "<DeclaringType>".` |

## Cause

When an aspect introduces an event with <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute> and sets its <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrFail>, PostSharp replaces or overrides the event of the same name that the target type already defines. When the delegate type of this event differs from the type of the introduced event, the introduced event cannot replace it, and PostSharp reports LA0064.

`<DeclaringType>` is the type that defines the existing event: the target type itself, or one of its base types.

## Resolution

* Give the introduced event and the existing event the same delegate type.
* Set the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> of the introduction to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrIgnore>: PostSharp then skips the introduction when the existing event has another type, and still overrides an event of the same type. <xref:PostSharp.Aspects.Advices.MemberOverrideAction.Ignore> skips the introduction whenever the event exists.
* Otherwise, rename the existing event or the introduced one.
