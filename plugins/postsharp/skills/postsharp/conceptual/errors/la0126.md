# LA0126: Aspect Applied to an Abstract Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Aspect "<Aspect>" cannot be applied to "<Target>" because the method is abstract.` |

## Cause

Some aspects work by adding code to the body of the target method. An abstract method has no body, so PostSharp reports LA0126 and skips the aspect when:

* an <xref:PostSharp.Aspects.OnMethodBoundaryAspect> or an <xref:PostSharp.Aspects.OnExceptionAspect> targets an abstract method of a class;
* a location validation aspect, which implements <xref:PostSharp.Aspects.ILocationValidationAspect`1>, targets a parameter or the return value of an abstract method.

`<Target>` is the method, or the parameter. For an abstract method of an interface, PostSharp reports <xref:la0130?text=LA0130> instead.

The usage of these two aspect classes excludes abstract methods, so when you apply them as custom attributes, multicasting skips the abstract methods. An aspect that an <xref:PostSharp.Aspects.IAspectProvider> provides is not filtered this way: its target is the declaration passed to the <xref:PostSharp.Aspects.AspectInstance> constructor. PostSharp then reports the message on the declaration that the provider is applied to.

## Resolution

* In the <xref:PostSharp.Aspects.IAspectProvider.ProvideAspects*> method, skip the methods whose <xref:System.Reflection.MethodBase.IsAbstract> property is `true`. Apply the aspect to the methods that override them instead.
* When you apply a location validation aspect to a parameter of an abstract method, apply it to the parameter of each overriding method instead.
