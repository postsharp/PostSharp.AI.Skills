# PS0023: Circular Reference Between Configuration Properties

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Error evaluating the expression "<Expression>": the maximum recursion level is reached. Check whether properties refer to each other in a cycle.` |

## Cause

The `Property` elements of a `postsharp.config` file can refer to other properties with expressions such as `{$TracingEnabled}`; see <xref:configuration-xpath>. A property with `Deferred="true"` keeps its expression and evaluates it every time the property is used, so it can refer to a property that is defined later. When deferred properties refer to each other in a cycle, directly or through other properties, their evaluation never ends. PostSharp stops when the references nest more than 32 levels deep and reports PS0023.

`<Expression>` is the expression that PostSharp was evaluating when it stopped, and the location of the message is the `Property` element that contains it, in one of the properties of the cycle.

A property without `Deferred="true"` is evaluated where it is defined, and a reference to a property that is not defined yet evaluates to an empty string, so a cycle needs at least one deferred property.

PostSharp reports PS0023 while it loads the configuration of the project, so it also reports <xref:ps0084?text=PS0084>, which says that the project could not be initialized.

## Resolution

Break the cycle: give one of the properties of the cycle a value that does not refer, directly or indirectly, to the property itself. To find the properties of the cycle, start from the `Property` element at the location of the message and follow its references.

When a property refers to itself to extend a value, for example `Value="{$Categories};Orders"`, remove `Deferred="true"`: the expression is then evaluated where the property is defined, with the value that the property had before.
