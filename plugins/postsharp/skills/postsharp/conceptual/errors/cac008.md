# CAC008: Method to Invalidate Not Found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Caching |
| **Message** | `Invalid [InvalidateCache] aspect on <Method>: there is no method named <MethodName> in type <Type>. To invalidate a method of another type, pass this type as the first argument of the [InvalidateCache] attribute.` |

## Cause

The <xref:PostSharp.Patterns.Caching.InvalidateCacheAttribute> aspect removes from the cache the values of the cached methods whose names you pass to its constructor. It looks for these methods in `<Type>`: the type that you pass as the first argument of the constructor or, when you pass only names, the type that declares the invalidating method `<Method>`. PostSharp reports CAC008 when `<Type>` has no method named `<MethodName>`, neither public nor private, neither static nor instance.

The most common cause is a cached method that belongs to another type, such as a repository, when the aspect does not name this type. The `nameof` operator does not help in this case: `nameof(CustomerRepository.GetCustomerName)` gives only the name `GetCustomerName`, not its type. A misspelled name in a string literal also causes the message.

PostSharp reports the message on the declaration of the invalidating method.

## Resolution

* When the cached method belongs to another type, pass this type as the first argument of the <xref:PostSharp.Patterns.Caching.InvalidateCacheAttribute> constructor, before the method names. If the cached method is an instance method and the invalidating method is not in the same type or a derived type, the instance must also be excluded from the cache key with the <xref:PostSharp.Patterns.Caching.CacheAttribute.IgnoreThisParameter> property, otherwise PostSharp reports <xref:cac003?text=CAC003>.
* Otherwise, correct the name, preferably with the `nameof` operator.
