# COM013: Relationship Attribute in a Class Without the Aggregatable Aspect

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Aggregation |
| **Message** | `The [<Attribute>] attribute applied to "<Member>" is ignored because the type <DeclaringType> does not have the [Aggregatable] aspect. Add the [Aggregatable] aspect to <DeclaringType>, or remove the attribute.` |

## Cause

The <xref:PostSharp.Patterns.Model.ChildAttribute>, <xref:PostSharp.Patterns.Model.ParentAttribute> and <xref:PostSharp.Patterns.Model.ReferenceAttribute> attributes describe the relationships of an object model, and only the <xref:PostSharp.Patterns.Model.AggregatableAttribute> aspect reads them. The threading models, such as <xref:PostSharp.Patterns.Threading.ThreadUnsafeAttribute>, add this aspect to their target class too. When none of these aspects is applied to the class that declares the field or the property, PostSharp reports COM013 once it has discovered all the aspects of the project, and the attribute has no effect: the object assigned to a `[Child]` property does not get a parent, for example.

`<Attribute>` is the type of the attribute. The current version of the message shows its full name, such as `PostSharp.Patterns.Model.ChildAttribute`.

## Resolution

* Add the `[Aggregatable]` aspect, or a threading model, to the class that declares the member.
* If the class is not part of an object model, remove the attribute.
