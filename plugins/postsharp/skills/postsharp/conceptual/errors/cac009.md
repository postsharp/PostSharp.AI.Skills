# CAC009: Several Overloads Match the Method to Invalidate

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Caching |
| **Message** | `Invalid [InvalidateCache] aspect on <Method>: there are several suitable overloads of the <MethodName> method. Set the AllowMultipleOverloads property to "true" to allow invalidation of all of them.` |

## Cause

The <xref:PostSharp.Patterns.Caching.InvalidateCacheAttribute> aspect identifies the methods to invalidate by name only. When the name designates several overloads, PostSharp keeps the cached overloads whose parameters can all be matched, by name and type, with the parameters of the invalidating method `<Method>`. An overload matches when the invalidating method has a parameter of the same name and of a compatible type for each of its parameters, except those marked with <xref:PostSharp.Patterns.Caching.NotCacheKeyAttribute>. An overload without parameters therefore matches any invalidating method.

When several overloads match, the aspect invalidates none of them by default, and PostSharp reports CAC009, so that you do not invalidate more cache items than you intend.

PostSharp reports the message on the declaration of the invalidating method.

## Resolution

* When the invalidating method makes all the matching overloads stale, set the <xref:PostSharp.Patterns.Caching.InvalidateCacheAttribute.AllowMultipleOverloads> property of the aspect to `true`. Each call then removes the cache items of every matching overload.
* Otherwise, give the overloads different names, so that the aspect can name only the one to invalidate.
