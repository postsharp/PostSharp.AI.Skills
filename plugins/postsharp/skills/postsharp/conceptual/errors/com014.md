# COM014: Collection Without Relationship Attribute in a Threading Model

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Aggregation |
| **Message** | `Field/property <DeclaringType>.<Member> is a collection and must be annotated with the custom attribute [Child] or [Reference]. The member has been assumed to be a reference for backward compatibility.` |

## Cause

The threading models, such as <xref:PostSharp.Patterns.Threading.ThreadUnsafeAttribute> or <xref:PostSharp.Patterns.Threading.SynchronizedAttribute>, add the <xref:PostSharp.Patterns.Model.AggregatableAttribute> aspect to their target class, in a compatibility mode. When a field, or an automatic property, can hold either a child or a reference and has no relationship attribute, the `[Aggregatable]` aspect alone reports the error <xref:com002?text=COM002>. In this compatibility mode, PostSharp treats the member as a reference instead, and reports COM014 when the type of the member is a collection, because a collection has no good default.

## Resolution

Annotate the member with one of the relationship attributes:

* <xref:PostSharp.Patterns.Model.ReferenceAttribute> when the class only refers to the collection or to its items. This keeps the behavior that PostSharp assumed.
* <xref:PostSharp.Patterns.Model.ChildAttribute> when the collection and its items belong to the class. A child collection must be an advisable collection, such as <xref:PostSharp.Patterns.Collections.AdvisableCollection`1>.
