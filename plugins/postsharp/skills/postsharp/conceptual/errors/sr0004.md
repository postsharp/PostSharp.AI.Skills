# SR0004: Read-Only Field in a PSerializable Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Field '<Field>' must not be read-only because its declaring type is [PSerializable].` |

## Cause

[<xref:PostSharp.Serialization.PSerializableAttribute>] serializes every instance field of the type, except the fields marked [<xref:PostSharp.Serialization.PNonSerializedAttribute>] and the fields of a delegate type. When <xref:PostSharp.Serialization.PortableFormatter> deserializes the object, the generated serializer first creates the instance, then assigns each of these fields. A `readonly` field can be assigned only in a constructor, so PostSharp reports SR0004 for the first read-only field that it would serialize.

The field can be a field that you wrote, or the backing field that C# generates for a get-only auto-property such as `public string Name { get; }`. In the second case, `<Field>` shows the name of the backing field, which contains the name of the property.

## Resolution

* Remove the `readonly` modifier of the field. For a get-only auto-property, add a setter, which can be `private`.
* When the field does not need to be serialized, for example because it is computed from other fields, mark it with [<xref:PostSharp.Serialization.PNonSerializedAttribute>].
