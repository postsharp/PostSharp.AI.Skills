# CAC002: Invalidated Method Is Not Cached

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Caching |
| **Message** | `The [InvalidateCache] aspect applied to <InvalidatingMethod> cannot invalidate <CachedMethod>: this method is not cached by the [Cache] aspect.` |

## Cause

The <xref:PostSharp.Patterns.Caching.InvalidateCacheAttribute> aspect removes from the cache the values of the methods that you name in its constructor, each time the method to which you apply it, `<InvalidatingMethod>`, is called. PostSharp looks for these methods by name in the type of `<InvalidatingMethod>`, or in the type that you pass to the constructor, and reports CAC002 when a method of that name, `<CachedMethod>`, exists but does not have the <xref:PostSharp.Patterns.Caching.CacheAttribute> aspect. The message is reported on `<InvalidatingMethod>`.

When several overloads have this name, PostSharp ignores the overloads that are not cached as long as one overload can be invalidated, and reports CAC002 for each of them only when none can.

## Resolution

* Add the `[Cache]` aspect to the method that you want to invalidate.
* If you named the wrong method, name the cached method instead. When the cached method belongs to another type, pass this type as the first argument of the constructor of `[InvalidateCache]`.
* If the method does not need to be cached, remove its name from the `[InvalidateCache]` aspect, or remove the aspect.
