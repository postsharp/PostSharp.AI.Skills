# PS0048: Task Required by a Library Not Found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot find the task "<TaskName>".` |

## Cause

PostSharp builds a project by running tasks. PostSharp and its plug-ins define these tasks with `TaskType` elements in their configuration files. A library can require a task in the projects that use it with <xref:PostSharp.Extensibility.RequirePostSharpAttribute>: when a project uses an attribute of the library that carries a <xref:PostSharp.Extensibility.RequirePostSharpAttribute>, PostSharp loads the plug-in that <xref:PostSharp.Extensibility.RequirePostSharpAttribute.PlugIn> names, if any, and adds the task that <xref:PostSharp.Extensibility.RequirePostSharpAttribute.Task> names.

PostSharp reports PS0048, and stops building the project, when no task of the name `<TaskName>` is defined, neither by PostSharp nor by the plug-ins that it has loaded. The usual causes are:

* The name of the task is misspelled in the <xref:PostSharp.Extensibility.RequirePostSharpAttribute> of the library.
* The task belongs to a version of the plug-in other than the one that the project uses, which does not define it, or defines it under another name.
* The <xref:PostSharp.Extensibility.RequirePostSharpAttribute> names the task, but not the plug-in that defines it.

The message does not name the declaration that requires the task. When you do not know it, search the referenced libraries for <xref:PostSharp.Extensibility.RequirePostSharpAttribute>.

## Resolution

* When you develop the library, give the exact name of the task, as the `Name` attribute of its `TaskType` element defines it, and the name of the plug-in that defines it when the task is not part of PostSharp.
* When the library comes from a NuGet package, check that the packages of the library and of its plug-ins have the same version, and update them together.
