# PS0276: Multicast Filter Property Has No Effect on This Declaration

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The property <Property> on <Attribute> does nothing when annotating <Declaration>. It only works when applied to <LegalTargets>.` |

## Cause

A multicast attribute, such as an aspect, can filter the declarations that it is multicast to by name. Each filter selects among the children of the declaration that the attribute is applied to, so it is meaningful only on some declarations:

| Property | Has an effect when the attribute is applied to |
|---|---|
| <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetAssemblies> | an assembly |
| <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetTypes> | an assembly |
| <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetMembers> | an assembly or a type |

PostSharp reports PS0276 when the attribute sets one of these properties on another declaration, for example <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetTypes> on a class, or <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetMembers> on a method. PostSharp ignores the property and multicasts the attribute as if the property were not set. `<LegalTargets>` names the declarations on which the property has an effect. The warning is reported on the declaration that carries the attribute.

This usually happens when an attribute written for the assembly level is copied onto a type.

## Resolution

* When the filter must select types or assemblies, move the attribute to the assembly, with the `[assembly: ...]` syntax.
* When the attribute is in the right place, remove the property: the declaration that the attribute is applied to already decides which types or members it reaches.

See <xref:attribute-multicasting> for the ways to filter the targets of an aspect.
