# LA0215: State Slot Bound with Different Types

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The [State] slot "<Slot>" has the type "<Type>" in the parameter "<Parameter>" of the advice "<Advice>", but the type "<OtherType>" in the parameter "<OtherParameter>" of the advice "<OtherAdvice>". All parameters bound to the same slot must have the same type.` |

## Cause

A parameter annotated with <xref:PostSharp.Aspects.Advices.StateAttribute> is bound to a variable that the advices of one group share for one execution of the target method. The variable is identified by its *slot*: the name of the parameter, or the slot name given to the <xref:PostSharp.Aspects.Advices.StateAttribute> constructor. Since one variable stores the value, all the parameters bound to a slot must have exactly the same type, whether they are passed by value or by reference. A base type, such as <xref:System.Object>, is not accepted.

PostSharp reports LA0215 when a parameter bound to a slot has another type than the first parameter bound to this slot in the group. `<Parameter>` and `<Advice>` designate the parameter that PostSharp reports, and `<OtherParameter>` and `<OtherAdvice>` the first parameter bound to the slot.
