# LA0234: FlowBehavior Parameter Overrides MethodExecutionArgs.FlowBehavior

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The advice "<Advice>" has both a MethodExecutionArgs parameter and the [FlowBehavior] parameter "<Parameter>". The value of the [FlowBehavior] parameter is used, and MethodExecutionArgs.FlowBehavior is ignored.` |

## Cause

An <xref:PostSharp.Aspects.Advices.OnMethodEntryAdvice>, an <xref:PostSharp.Aspects.Advices.OnMethodExceptionAdvice> or an <xref:PostSharp.Aspects.Advices.OnMethodResumeAdvice> can change the control flow of the target method in two ways: through the <xref:PostSharp.Aspects.MethodExecutionArgs.FlowBehavior> property of a <xref:PostSharp.Aspects.MethodExecutionArgs> parameter, or through a parameter annotated with <xref:PostSharp.Aspects.Advices.FlowBehaviorAttribute>. When the advice has both, the woven code reads only the `[FlowBehavior]` parameter, and PostSharp reports LA0234 on this parameter, whatever values the advice sets.

In the following example, the `[SkipWhenOffline]` aspect sets `args.FlowBehavior` to <xref:PostSharp.Aspects.FlowBehavior.Return?text=FlowBehavior.Return>, but leaves the `[FlowBehavior]` parameter at its default value, so `Synchronize` still runs.

## Resolution

Set the flow behavior in one way only:

* Remove the `[FlowBehavior]` parameter, and set <xref:PostSharp.Aspects.MethodExecutionArgs.FlowBehavior>.
* Or remove the <xref:PostSharp.Aspects.MethodExecutionArgs> parameter, and get the values that the advice reads from it through other bound parameters, such as <xref:PostSharp.Aspects.Advices.DeclarationNameAttribute> for the name of the method.
