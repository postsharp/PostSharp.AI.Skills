# PS0263: Item Cannot Be Added to a Collection in a Configuration File

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot add <Item> to <Collection>: <Reason>` |

## Cause

Some sections of a `postsharp.config` file, such as the `Logging` element, describe objects in XML. An element named after a collection property, such as `Profiles`, contains the items of the collection, and PostSharp adds each item to the collection in turn. PostSharp reports PS0263 on the item element when the collection refuses the item:

* `<Item>` is the item, for example `{LoggingProfile Name="Orders"}`.
* `<Collection>` is the type and the property of the collection, for example `PostSharp.Patterns.Diagnostics.LoggingBuildTimeConfiguration.Profiles`.
* `<Reason>` is the message of the exception that the collection threw.

The collection of logging profiles is indexed by the name of the profile, ignoring case, so two `LoggingProfile` elements with the same `Name` in the same `Logging` element report PS0263 on the second one. PostSharp skips the item and goes on reading the file to report the other mistakes it finds.

## Resolution

Give each item a unique name. When the two elements describe the same logging profile, merge their options into one `LoggingProfile` element. When they describe different profiles, rename one of them, and use the new name in the <xref:PostSharp.Patterns.Diagnostics.LogAttribute> instances that refer to it.

To change a profile that another `postsharp.config` file defines, for example a file of the solution, define the profile in the `postsharp.config` of the project instead of repeating it in the same file: PostSharp merges the profiles of different files by name.
