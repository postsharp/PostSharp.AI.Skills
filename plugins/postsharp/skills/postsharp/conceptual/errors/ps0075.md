# PS0075: Compile Task Signs the Assembly Without a Private Key

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Compile task: one of the properties 'PrivateKeyLocation' or 'PrivateKeyContainer' should be set when the property 'SignAssembly' is true.` |

## Cause

The last step of the PostSharp compiler is the `Compile` task, which writes the woven assembly. PostSharp configures this task itself. A configuration file, such as `postsharp.config` or a `.psproj` file, can replace this configuration with a `Compile` element in a `Tasks` section, a practice of old PostSharp projects.

When the `SignAssembly` attribute of this element is true, PostSharp must sign the woven assembly, so it needs a private key: a key file in the `PrivateKeyLocation` attribute, or the name of a key container in the `PrivateKeyContainer` attribute. PostSharp reports PS0075 when both are missing or empty.

PostSharp then cannot set up the project and also reports <xref:ps0084?text=PS0084>.

## Resolution

* Remove the `Compile` element, and the `Tasks` section, from the configuration file. PostSharp then configures the `Compile` task itself and signs the woven assembly when the project is signed, with the `SignAssembly` and `AssemblyOriginatorKeyFile` MSBuild properties.
* When you keep the element, remove the `SignAssembly` attribute, or give the private key in the `PrivateKeyLocation` or `PrivateKeyContainer` attribute.
