# THR009: Actor Method Has a By-Reference Parameter

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Method "<Method>" cannot have ref, out or in parameters because its declaring class has the [Actor] threading model and the method can be invoked from outside the object. Return the value through a Task<T> instead.` |

## Cause

The <xref:PostSharp.Patterns.Threading.ActorAttribute> aspect does not execute a call to an actor in the thread of the caller: it adds the call to the message queue of the actor, which executes the calls one after the other. A by-reference parameter refers to a variable of the caller, which the actor would read or write later, from another thread. PostSharp therefore reports THR009 for a method of an actor that has a `ref`, `out` or `in` parameter and is an entry point of the object, that is, a method that can be invoked from outside the object:

* a `public`, `internal` or `protected internal` method;
* a method that implements an interface;
* a protected method that overrides a method of a base class without a threading model;
* a method with the <xref:PostSharp.Patterns.Threading.EntryPointAttribute> custom attribute.

Private methods are not dispatched, because only the actor calls them, so they can have by-reference parameters.

## Resolution

* To return a value, make the method `async` and return a `Task<T>`, which the caller awaits. In an actor, an `async` method must also have the <xref:PostSharp.Patterns.Threading.ReentrantAttribute> custom attribute; otherwise, PostSharp reports <xref:thr017?text=THR017>.
* To pass several values to the actor or receive several values from it, group them in a type instead of using by-reference parameters.
* When the method does not need to be an entry point of the actor, make it private.
