# LA0222: Address of a Bound Argument Is Not Available

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is bound by reference to the argument at index <Index> of "<Target>", but the address of this argument cannot be loaded in this advice. This happens when the method has more than eight parameters and PostSharp stores its arguments in an array.` |

## Cause

A parameter of an advice annotated with <xref:PostSharp.Aspects.Advices.ArgumentAttribute> and passed as `ref`, `out` or `in` receives the address of an argument of the target method, so that the advice can read or replace the argument. PostSharp loads this address when it generates the code of the advice. When it cannot, it reports LA0222 on the target method. `<Index>` is the zero-based index of the argument.

The address is not available when PostSharp keeps the arguments in an <xref:PostSharp.Aspects.Arguments> object instead of the parameters or the fields of a state machine, and the method has more than eight parameters: the arguments are then stored as objects in an array, which has no field of the type of the argument. This happens when a method boundary advice is applied to a method that returns a task but is not `async`: PostSharp generates the state machine of this method, and stores the arguments in an <xref:PostSharp.Aspects.Arguments> object.

## Resolution

* Make the method `async`. The advice then runs in the state machine that the C# compiler generates, which stores each argument in a field of its own type.
* Reduce the number of parameters of the method to eight or fewer, for example by grouping them into a class or a record.
* Bind the argument by value, when the advice only reads it.
