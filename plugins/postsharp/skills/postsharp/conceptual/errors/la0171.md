# LA0171: Fallback Without an OnInvoke Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Aspect "<Aspect>" does not implement the non-async OnInvoke advice, therefore the UnsupportedTargetAction property cannot be set to Fallback.` |

## Cause

A <xref:PostSharp.Aspects.MethodInterceptionAspect> that overrides <xref:PostSharp.Aspects.MethodInterceptionAspect.OnInvokeAsync(PostSharp.Aspects.MethodInterceptionArgs)> intercepts the tasks of the methods that return a <xref:System.Threading.Tasks.Task> or a <xref:System.Threading.Tasks.Task`1>. Async interception does not support other targets, such as `async void` methods and methods that return a <xref:System.Threading.Tasks.ValueTask`1>. The <xref:PostSharp.Aspects.MethodInterceptionAspect.UnsupportedTargetAction> property says what PostSharp does with them, and <xref:PostSharp.Aspects.UnsupportedTargetAction.Fallback> means that <xref:PostSharp.Aspects.MethodInterceptionAspect.OnInvoke(PostSharp.Aspects.MethodInterceptionArgs)> intercepts them without async semantics.

PostSharp reports LA0171 when the property is set to <xref:PostSharp.Aspects.UnsupportedTargetAction.Fallback> and the aspect does not override <xref:PostSharp.Aspects.MethodInterceptionAspect.OnInvoke(PostSharp.Aspects.MethodInterceptionArgs)>: there is nothing to fall back to. PostSharp checks this for every target of the aspect, also for the targets that async interception supports, and reports the error on the target method.

## Resolution

* Override <xref:PostSharp.Aspects.MethodInterceptionAspect.OnInvoke(PostSharp.Aspects.MethodInterceptionArgs)> in the aspect, so that PostSharp can intercept the unsupported targets without async semantics.
* Otherwise, set <xref:PostSharp.Aspects.MethodInterceptionAspect.UnsupportedTargetAction> to <xref:PostSharp.Aspects.UnsupportedTargetAction.Ignore> to leave the unsupported targets alone, or remove the property to get an error on each of them.
