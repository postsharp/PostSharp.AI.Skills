# PS0132: Other Licensing Problem

| | |
|---|---|
| **Severity** | Warning or Error |
| **Reported by** | PostSharp |
| **Message** | `<Reason>` |

## Cause

Before it builds a project, PostSharp asks its licensing services to read the license keys and license servers that the project and the machine supply, and to check that a license covers what the project uses. The licensing services compose a message for each problem that they find, and PostSharp reports this message under the diagnostic that describes the situation:

* <xref:ps0242?text=PS0242> when no usable license was found at all, and <xref:ps0127?text=PS0127> when the licenses found do not cover a feature.
* <xref:ps0148?text=PS0148> when a license server does not lease a license.
* <xref:ps0301?text=PS0301> when a license key is invalid, is limited to another namespace, or licenses another product.
* <xref:ps0304?text=PS0304> when a license key has expired or has been revoked.
* <xref:ps0305?text=PS0305> when a license server is reached over HTTP.

PostSharp reports PS0132 for any other message of the licensing services. `<Reason>` is the complete text that the licensing services composed. The licensing services decide whether the message is an error or a warning; most messages of this kind are warnings.

In this version of PostSharp, the licensing services classify the problems that a build can meet under one of the messages above, so PS0132 is rare. This message depends on the license of the machine and on the licensing services, so no example can show it.

## Resolution

* Read `<Reason>`: it says which license key or license source has the problem.
* Check the license keys of the project and of the machine. See <xref:deploying-keys> for the places where PostSharp reads them.
* Capture the licensing trace with the `PostSharpTrace` MSBuild property, as <xref:license-troubleshooting> describes, to see which keys PostSharp considers and what it does with them.
