# LA0204: Aspect Applied to a Function Pointer

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to the target element "<Target>". Applying aspects to fields, properties, and parameters of method pointer type is not supported.` |

## Cause

PostSharp does not support function pointers, declared with `delegate*` in unsafe C# code, as the type of an element that an aspect intercepts or whose value it receives. It reports LA0204 when an aspect or an advice targets:

* a field or a property of function pointer type, for example with a <xref:PostSharp.Aspects.LocationInterceptionAspect>;
* a parameter of function pointer type, for example with a <xref:PostSharp.Aspects.LocationLevelAspect> that validates parameters;
* a method that has a parameter of function pointer type, for example with an <xref:PostSharp.Aspects.OnMethodBoundaryAspect>.

`<Target>` is the element that the aspect or the advice targets.

## Resolution

* Change the type of the field, property or parameter to a delegate type, such as <xref:System.Func`2>, which PostSharp supports.
* Otherwise, exclude the element from the aspect. When the aspect is multicast, exclude the element with <xref:PostSharp.Extensibility.MulticastAttribute.AttributeExclude>, or set the <xref:PostSharp.Aspects.Aspect.UnsupportedTargetAction> property of the aspect (or the `UnsupportedTargetAction` property of the advice, in a composite aspect) to <xref:PostSharp.Aspects.UnsupportedTargetAction.Ignore>, so that PostSharp skips the unsupported elements without a message.
