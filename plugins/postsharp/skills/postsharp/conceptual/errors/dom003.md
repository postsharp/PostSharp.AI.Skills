# DOM003: Property Getter Creates a Delegate

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Model |
| **Message** | `NotifyPropertyChangedAttribute: automatic analysis of property <Property> failed. Method <Method> creates a delegate, which cannot be analyzed. To solve this error, create the delegate outside of the code that the property getter executes, for example in the constructor. To ignore the delegate, add the [SafeForDependencyAnalysis] attribute to the property <Property>.` |

## Cause

The <xref:PostSharp.Patterns.Model.NotifyPropertyChangedAttribute> aspect analyzes the getter of each property at build time to find the fields and properties that its value depends on. It cannot follow a delegate, so PostSharp reports DOM003 when the getter creates one, from a method group such as `this.Save` or from a lambda expression, for example one passed to a LINQ method.

The message is about the creation of the delegate. Calling a delegate in the getter reports <xref:dom011?text=DOM011>, because the `Invoke` method of a delegate is virtual, so a getter that creates a delegate and calls it reports both messages. A call to a static method that receives the delegate, such as a LINQ method, can also report <xref:dom002?text=DOM002>, because a delegate argument is not of an immutable type.

`<Method>` is the method that creates the delegate: the getter itself, or a method of the same class that the getter calls. PostSharp reports the message on the property.

## Resolution

* Create the delegate once, outside of the getter, for example in the constructor, and store it, or the object that holds it, in a field or a read-only property.
* When the delegate does not change the dependencies of the property, add the <xref:PostSharp.Patterns.Model.SafeForDependencyAnalysisAttribute> attribute to the property, and declare the dependencies hidden behind the delegate with <xref:PostSharp.Patterns.Model.Depends.On*>.
