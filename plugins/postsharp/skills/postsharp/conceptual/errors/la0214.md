# LA0214: Binding Used Twice in One Advice

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is bound by <Binding>, but the advice already has a parameter bound by <Binding>.` |

## Cause

An advice can have at most one parameter annotated with <xref:PostSharp.Aspects.Advices.ExceptionAttribute> and one annotated with <xref:PostSharp.Aspects.Advices.ReturnValueAttribute>, because the exception and the return value are single values. PostSharp reports LA0214 on the second such parameter of the advice. `<Binding>` is the binding attribute, `[Exception]` or `[ReturnValue]`.

Most other bindings can be used several times in one advice, for instance to bind two arguments. Several `[FlowBehavior]` or `[Awaiter]` parameters cause the warning <xref:la0236?text=LA0236> instead.

## Resolution

Keep one parameter with the binding. To read a value and replace it, declare this parameter as `ref`: an `[Exception]` parameter passed as `ref` receives the exception, and the value that the advice assigns to it is the exception that <xref:PostSharp.Aspects.FlowBehavior.ThrowException?text=FlowBehavior.ThrowException> throws. A `[ReturnValue]` parameter passed as `ref` works the same way in the advices that accept it. See [Handling exceptions](xref:advice-parameter-binding#handling-exceptions).
