# LA0286: Several Properties Can Provide the Dependency

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The aspect "<Aspect>" applied to "<Target>" attempts to introduce a dependency of type "<DependencyType>" in "<TargetType>", and several existing properties of this type could provide it instead: <Properties>. Remove all but one of these properties, or give the class a field of type "<DependencyType>" that stores the dependency.` |

## Cause

When an aspect attempts to introduce a dependency with an <xref:PostSharp.Aspects.Advices.ImportDependencyAdviceInstance>, PostSharp first looks for a member of `<TargetType>` that already holds the dependency:

1. A field of the dependency type, declared by the class, or by a base class when the class can access it.
2. A property that PostSharp created for the same dependency of a base class.
3. A readable instance property of the dependency type, without parameters, declared by the class, or by a base class when the class can access its getter. The class initializes this property itself, so PostSharp uses it and does not add any parameter to the constructors.

When none of these members exists, PostSharp introduces a field and adds a parameter of the dependency type to the constructors. PostSharp reports LA0286 when step 3 finds several properties: it cannot choose which one provides the dependency. `<Properties>` lists these properties, and `<Target>` is the declaration to which the aspect is applied, where the error is located. LA0286 is always an error.

PostSharp looks for these members by their type only. The <xref:PostSharp.Aspects.Advices.ImportDependencyAdviceInstance.Name> of the request does not change the search: it is the name by which the advices import the dependency.

When the advice imports the dependency by its type, with <xref:PostSharp.Aspects.Advices.ImportMemberAttribute>, the same properties also make this import ambiguous, so PostSharp also reports <xref:la0283?text=LA0283> for the advice parameter. Both errors disappear with the same fix.

## Resolution

* Keep only one property of the dependency type, so that this property provides the dependency.
* Otherwise, declare a field of the dependency type in the class, and assign it the dependency. PostSharp uses this field before it looks at the properties.
