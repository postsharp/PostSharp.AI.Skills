# PS0261: Invalid Compatibility Level

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The CompatibilityLevel property has the invalid value '<Value>', which PostSharp ignores. Set it to a version with at least a major and a minor number, such as 2027.0, usually with the MSBuild property PostSharpCompatibilityLevel.` |

## Cause

The compatibility level is the version of PostSharp whose behavior PostSharp keeps where a later version changed it. You usually set it with the `PostSharpCompatibilityLevel` MSBuild property, which PostSharp receives as its `CompatibilityLevel` property; see <xref:msbuild-properties>. PostSharp reads the value only when a behavior depends on it, for example the path of an exception thrown by the `OnYield` or `OnResume` advice of an `async` method.

PostSharp reports PS0261 when the value is not a version in the sense of <xref:System.Version>, with at least a major and a minor number. A year alone, such as `2027`, is not a valid version. PostSharp then ignores the value and behaves as if the property were not set. The message has no source location.

In the following example, the compatibility level is `2027`, and the `[Profile]` aspect has `OnYield` and `OnResume` advices on an `async` method. Because PostSharp ignores the value, the project behaves as if it set no compatibility level, so PostSharp also reports <xref:la0250?text=LA0250> on the method.

## Resolution

Set the compatibility level to a version with a major and a minor number, such as `2027.0`:

```xml
<PropertyGroup>
  <PostSharpCompatibilityLevel>2027.0</PostSharpCompatibilityLevel>
</PropertyGroup>
```

When the property is set in the `PostSharpProperties` MSBuild property or in another place, correct the value there.
