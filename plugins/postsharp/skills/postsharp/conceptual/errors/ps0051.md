# PS0051: Multicast Attribute Class Without Usage

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The type "<Type>" or one of its ancestors should be decorated by an instance of MulticastAttributeUsageAttribute.` |

## Cause

PostSharp multicasts an attribute derived from <xref:PostSharp.Extensibility.MulticastAttribute> to the declarations that its <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute> allows: for example, from a class to its methods. See <xref:multicast-conceptual>. An attribute class inherits this usage from its base classes. The aspect classes of PostSharp, such as <xref:PostSharp.Aspects.OnMethodBoundaryAspect>, already carry one, but <xref:PostSharp.Extensibility.MulticastAttribute> itself does not.

PostSharp reports PS0051 on the attribute class `<Type>` when you apply it in the project, and neither the class nor any of its base classes carry a <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute>. This usually happens with a class derived directly from <xref:PostSharp.Extensibility.MulticastAttribute>, for example a marker attribute that you want to multicast without adding any behavior. PostSharp then skips the instances of the attribute, and reports <xref:ps0055?text=PS0055> because it cannot continue after this error.

## Resolution

Add a <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute> to the attribute class, or to a base class of it, and set its <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute.ValidOn> property to the kinds of declarations on which the attribute can end up. By default, the compiled assembly does not contain the instances of a multicast attribute: set <xref:PostSharp.Extensibility.MulticastAttributeUsageAttribute.PersistMetaData> to `true` when the program reads the attribute with reflection. See <xref:multicast-reflection>.
