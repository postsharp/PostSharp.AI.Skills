# LA0193: Introduced Attribute Type Name Is Not Assembly-Qualified

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to target "<Target>": the type name "<TypeName>" of the custom attribute to introduce is not an assembly-qualified type name. Include the name of the assembly, or create the ObjectConstruction from a Type.` |

## Cause

An aspect provider introduces a custom attribute by providing a <xref:PostSharp.Aspects.CustomAttributeIntroductionAspect>, which receives the attribute as a <xref:PostSharp.Reflection.ObjectConstruction>. When the <xref:PostSharp.Reflection.ObjectConstruction> is created from a type name, PostSharp needs the name of the assembly to find the type, so the name must be assembly-qualified, such as `MyCompany.AuditTrailAttribute, MyCompany.Core`. PostSharp reports LA0193 when the name has no assembly part.

`<Aspect>` is <xref:PostSharp.Aspects.CustomAttributeIntroductionAspect>, not the aspect that provides it, and `<Target>` is the declaration that should receive the attribute.

## Resolution

* Create the <xref:PostSharp.Reflection.ObjectConstruction> from the <xref:System.Type> of the attribute when the aspect can reference it: the constructor that takes a `Type` uses its assembly-qualified name.
* Otherwise, add the name of the assembly to the type name, after a comma.
