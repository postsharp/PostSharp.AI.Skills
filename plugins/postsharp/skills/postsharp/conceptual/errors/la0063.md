# LA0063: Introduced Property Has a Different Type than the Existing Property

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot introduce property "<Property>" into type "<TargetType>" because a property with the same name and parameters, but of a different type, is defined in type "<DeclaringType>".` |

## Cause

When an aspect introduces a property with <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute> and sets its <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrFail>, PostSharp replaces or overrides the property that the target type already defines. The existing property is the one with the same name and the same index parameters. When the type of this property differs from the type of the introduced property, the introduced property cannot replace it, and PostSharp reports LA0063.

`<DeclaringType>` is the type that defines the existing property: the target type itself, or one of its base types.

## Resolution

* Give the introduced property and the existing property the same type.
* Set the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> of the introduction to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrIgnore>: PostSharp then skips the introduction when the existing property has another type, and still overrides a property of the same type. <xref:PostSharp.Aspects.Advices.MemberOverrideAction.Ignore> skips the introduction whenever the property exists.
* Otherwise, rename the existing property or the introduced one.
