# PS0161: Invalid CLR Namespace in a Configuration File

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot parse the XML namespace '<XmlNamespace>': the expected format is 'clr-namespace:MyNamespace;assembly:MyAssembly'.` |

## Cause

In some sections of a PostSharp configuration file, such as the `Multicast` section and the logging profiles, each XML element describes a CLR object: an aspect, an attribute or a logging option. PostSharp finds the type of the object from the XML namespace of the element, which must have the form `clr-namespace:MyNamespace;assembly:MyAssembly`: pairs separated by a semicolon, each with a key and a value separated by a colon, with exactly the keys `clr-namespace` and `assembly`.

PostSharp reports PS0161 when `<XmlNamespace>` does not have this form, and ignores the element. The common causes are:

* The assembly is introduced with `assembly=`, as in XAML, instead of `assembly:`.
* The `assembly` part is missing.
* The element has no prefix and inherits the default namespace of the file, `http://schemas.postsharp.org/1.0/configuration`.

## Resolution

Write the XML namespace in the form `clr-namespace:MyNamespace;assembly:MyAssembly`, where `MyNamespace` is the namespace of the type and `MyAssembly` is the name of the assembly that declares it, without the `.dll` extension. Give each element that describes an object the prefix of this namespace.
