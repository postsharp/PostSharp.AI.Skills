# LA0180: Method Boundary Aspect Applied to a Static Constructor of Another Assembly

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to the static constructor of type "<Type>": applying OnMethodBoundaryAspect or OnExceptionAspect to a static constructor of another assembly is not supported. Restrict the aspect to methods.` |

## Cause

PostSharp can apply an aspect to a method of a referenced assembly without modifying that assembly: it replaces the calls that the current assembly makes to the method with calls to a generated method that runs the aspect. A static constructor is never called by your code, but by the runtime, so PostSharp reports LA0180 when an <xref:PostSharp.Aspects.OnMethodBoundaryAspect> or an <xref:PostSharp.Aspects.OnExceptionAspect> targets the static constructor of a type of another assembly. `<Type>` is the type that declares the static constructor. The message has no location in the source code.

Multicasting with <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetAssemblies> only reaches the members of another assembly that the current assembly references, which never include a static constructor. The message comes from an <xref:PostSharp.Aspects.IAspectProvider> that provides the aspect for the static constructor explicitly, for example from <xref:System.Type.TypeInitializer>.

## Resolution

* Provide the aspect for methods only, not for the static constructor.
* When you own the library, apply the aspect in the library itself, where PostSharp can enhance the static constructor.
