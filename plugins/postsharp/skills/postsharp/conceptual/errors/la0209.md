# LA0209: Advice Does Not Accept Binding Attributes

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" has an advice parameter attribute, but advices of the kind "<AdviceKind>" do not accept advice parameter bindings.` |

## Cause

Only some kinds of advices accept parameters annotated with a binding attribute: the method boundary advices, <xref:PostSharp.Aspects.Advices.OnMethodInvokeAdvice>, <xref:PostSharp.Aspects.Advices.OnLocationGetValueAdvice>, <xref:PostSharp.Aspects.Advices.OnLocationSetValueAdvice> and <xref:PostSharp.Aspects.Advices.OnInstanceConstructedAdvice>. The code that PostSharp generates for the other advices passes them only their <xref:PostSharp.Aspects.AdviceArgs> object. When a parameter of such an advice has a binding attribute, PostSharp cannot pass a value to it, and reports LA0209 on the parameter.

The advices that do not accept bound parameters include <xref:PostSharp.Aspects.Advices.OnInstanceLocationInitializedAdvice>, <xref:PostSharp.Aspects.Advices.OnMethodInvokeAsyncAdvice> and the event interception advices. `<AdviceKind>` is the full name of the attribute of the advice.

## Resolution

* Remove the bound parameter, and read the value from the <xref:PostSharp.Aspects.AdviceArgs> object of the advice. For instance, <xref:PostSharp.Aspects.LocationInitializationArgs> gives the name of the field or property and its value.
* Otherwise, move the parameter to an advice of a kind that accepts it. The table in [Bindings by advice kind](xref:advice-parameter-binding#bindings-by-advice-kind) shows the binding attributes that each advice accepts.
