# LA0192: Introduced Method Differs from the Existing Method by an In Modifier

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot introduce method "<Method>" into type "<TargetType>" because it is already defined in type "<DeclaringType>" with a parameter that is 'in' in one method and 'ref' or 'out' in the other.` |

## Cause

An aspect introduces a method into its target type with <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute>, and the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> of the introduction lets it replace or override an existing method, for example <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrFail>.

In the compiled code, `in`, `ref` and `out` parameters have the same type, a reference to the value, so PostSharp finds the existing method although the C# declarations differ. An `in` parameter is read-only, while a `ref` or `out` parameter can be written to, so PostSharp does not let one method replace the other. It reports LA0192 when a parameter is `in` in one of the two methods and `ref` or `out` in the other.

`<DeclaringType>` is the type that defines the existing method: the target type itself, or one of its base types. The message has no location in the source code.

## Resolution

Give each parameter the same modifier in the introduced method and in the existing method: `in` in both, or `ref` in both. Otherwise, rename one of the two methods, or set <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.Ignore> to keep the existing method.
