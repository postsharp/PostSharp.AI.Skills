# LA0032: Aspect Provided to a Parameter of an Unknown Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect <Aspect> to a parameter of method <DeclaringType>.<Method> because PostSharp cannot find this method in the current assembly or in the assemblies that it references.` |

## Cause

An aspect that implements <xref:PostSharp.Aspects.IAspectProvider> adds aspects to other declarations by returning <xref:PostSharp.Aspects.AspectInstance> objects from its <xref:PostSharp.Aspects.IAspectProvider.ProvideAspects*> method. The target element of each <xref:PostSharp.Aspects.AspectInstance> is a reflection object, which PostSharp maps back to a declaration of the code that it compiles. When the target element is a parameter, PostSharp looks for the method that declares it. If it cannot find this method in the current assembly or in the assemblies that the project references, it reports LA0032.

This happens when the reflection object does not describe the code that you compile, but an implementation detail of the .NET runtime that no reference assembly exposes. The most common mistake is to call `GetType()` on the target element: the target element of a type-level aspect is already a <xref:System.Type>, so `GetType()` returns `System.RuntimeType`, the class of reflection objects, and its methods are internal to the runtime. PostSharp reports LA0032 once for each parameter that the provider returns, on the aspect provider class.

## Resolution

Get the parameters from the target element itself: cast it to <xref:System.Type> in a type-level aspect, or to <xref:System.Reflection.MethodBase> in a method-level aspect, instead of calling `GetType()`. More generally, provide aspects only to parameters of methods of the current assembly, which are the only ones that PostSharp can transform; the `DeclaredOnly` binding flag excludes the methods that the target type inherits.
