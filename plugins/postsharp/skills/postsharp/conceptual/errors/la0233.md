# LA0233: Binding Ignored in This Kind of Advice

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is bound by <Binding>, which is not supported in this advice: the value of the parameter is ignored or not defined. <Binding> is supported only in these advices: <SupportedAdvices>.` |

## Cause

Each binding attribute of an advice parameter is accepted only in some kinds of advice. Most bindings cause the error <xref:la0151?text=LA0151> in an advice that does not accept them. Two bindings cause this warning instead, because the woven code still builds:

* <xref:PostSharp.Aspects.Advices.FlowBehaviorAttribute> is read only after an <xref:PostSharp.Aspects.Advices.OnMethodEntryAdvice>, an <xref:PostSharp.Aspects.Advices.OnMethodExceptionAdvice> or an <xref:PostSharp.Aspects.Advices.OnMethodResumeAdvice>. In another advice, such as <xref:PostSharp.Aspects.Advices.OnMethodExitAdvice> or <xref:PostSharp.Aspects.Advices.OnMethodSuccessAdvice>, the value that the advice sets is ignored.
* <xref:PostSharp.Aspects.Advices.ArgumentsAttribute> is defined only in the method boundary advices and in <xref:PostSharp.Aspects.Advices.OnMethodInvokeAdvice>. In a location interception advice, the value of the parameter is not defined.

`<Binding>` is the binding attribute, such as `[FlowBehavior]`, and `<SupportedAdvices>` lists the advice attributes that accept it.

## Resolution

* Move the parameter to an advice that accepts it, as `<SupportedAdvices>` lists. To swallow an exception, set the flow behavior in an <xref:PostSharp.Aspects.Advices.OnMethodExceptionAdvice>.
* When the advice does not need the value, remove the parameter.
