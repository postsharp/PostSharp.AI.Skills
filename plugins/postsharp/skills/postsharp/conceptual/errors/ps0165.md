# PS0165: Type in a Configuration File Has No Parameterless Constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The type '<ElementName>' does not have a default constructor.` |

## Cause

In some sections of a PostSharp configuration file, such as the `Multicast` section and the logging profiles, each XML element describes a CLR object. PostSharp creates the object with the constructor of the type that has no parameters, then sets its fields and properties from the XML attributes of the element. Unlike a custom attribute in C#, an XML element cannot pass constructor arguments.

PostSharp reports PS0165 when the type has no constructor without parameters, and ignores the element. `<ElementName>` is the local name of the XML element, which can omit the `Attribute` suffix of the type name.

## Resolution

Add a parameterless constructor to the type, and expose each value that a constructor parameter receives as a public property or field, which the XML element can set as an attribute. You can keep the other constructors for the code that uses the type as a custom attribute.
