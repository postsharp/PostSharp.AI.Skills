# THR001: Method Cannot Be Dispatched in Non-Blocking Mode

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Method "<Method>" cannot be enhanced with the [Dispatched] aspect in non-blocking mode. When the ExecutionMode property is NonBlocking or NonBlockingContextSwitch, for example with [Dispatched(true)], this aspect can only be applied 1) to void methods with no ref, out or in parameters; 2) to async methods with return type void, Task or Task<T>.` |

## Cause

The <xref:PostSharp.Patterns.Threading.DispatchedAttribute> aspect executes a method in the thread of the object, typically the UI thread. In non-blocking mode, the caller does not wait for the method: it enqueues the call and continues immediately. The aspect is in non-blocking mode when you pass `true` to its constructor, or when you set its <xref:PostSharp.Patterns.Threading.DispatchedAttribute.ExecutionMode> property to <xref:PostSharp.Patterns.Threading.DispatchedExecutionMode.NonBlocking> or <xref:PostSharp.Patterns.Threading.DispatchedExecutionMode.NonBlockingContextSwitch>.

Because the caller does not wait, it cannot receive a return value or the values of `ref` and `out` parameters. PostSharp therefore reports THR001 when a method dispatched in non-blocking mode is:

* a method without the `async` keyword whose return type is not `void`, including a method that returns a `Task` without being `async`;
* an `async` method whose return type is neither `void` nor `Task` or `Task<T>`, for example `ValueTask<T>`;
* a method with a `ref`, `out` or `in` parameter.

## Resolution

* When the caller needs the result of the method, use the blocking mode, which is the default: remove the `true` argument, or set <xref:PostSharp.Patterns.Threading.DispatchedAttribute.ExecutionMode> to <xref:PostSharp.Patterns.Threading.DispatchedExecutionMode.Blocking>. The caller then waits for the method to complete in the thread of the object.
* When the caller should not wait, make the method `async` and return a `Task` or a `Task<T>`, or return `void` and remove the `ref`, `out` and `in` parameters.
