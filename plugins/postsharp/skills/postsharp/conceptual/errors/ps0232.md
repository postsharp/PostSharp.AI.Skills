# PS0232: No Input Assembly Specified

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `No input specified. Specify input in the command line or using property "Input".` |

## Cause

The PostSharp compiler processes one assembly, which the `Input` property of the PostSharp project names. In a normal build, the MSBuild targets of PostSharp set this property to the assembly that the C# compiler has just produced, which they move to the `BeforePostSharp` folder under the intermediate output directory (`obj`) of the project.

PostSharp reports PS0232 when the `Input` property is empty while PostSharp loads the project. It is a fatal error: PostSharp stops at once. This happens when the PostSharp compiler is invoked directly, from the command line or from a custom build script, without an input file, or when a customization of the build clears the property.

The MSBuild targets of PostSharp always set the `Input` property, so no example can show this message.

## Resolution

* When you invoke the PostSharp compiler directly, pass the path of the assembly to process in the command line, or set the `Input` property.
* When you customized the MSBuild targets of PostSharp, or pass PostSharp properties through the `PostSharpProperties` MSBuild property, check that they do not set `Input` to an empty value. To see the properties that PostSharp receives, build with a detailed verbosity (`dotnet build -v:d`).
* Otherwise, let the PostSharp NuGet package build the project: remove the custom invocation and use the MSBuild targets of the package. See <xref:msbuild-properties>.
