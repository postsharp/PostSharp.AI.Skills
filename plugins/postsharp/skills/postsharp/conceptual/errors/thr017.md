# THR017: Async Method Must Be Reentrant

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `The async method "<Method>" must be annotated with the [Reentrant] custom attribute because the <ThreadingModel> threading model does not support non-reentrant async methods. A reentrant method releases the exclusivity guaranteed by the <ThreadingModel> model before awaiting and acquires it again when it resumes. Note that reacquiring a lock on resume makes the executing thread wait synchronously instead of awaiting the lock asynchronously.` |

## Cause

An `async` method returns to its caller at its first `await` that does not complete immediately, and resumes later, often in another thread. A threading model that gives a thread exclusive access to the object cannot keep this access while the method awaits: it would hold a lock across threads, or block the queue of an actor. PostSharp supports only reentrant async methods, which release the exclusive access before each `await` and acquire it again when they resume. Because another thread can then access the object while the method awaits, you must confirm this behavior with the <xref:PostSharp.Patterns.Threading.ReentrantAttribute> custom attribute.

PostSharp reports THR017 for an `async` method without this attribute when:

* the class has the <xref:PostSharp.Patterns.Threading.SynchronizedAttribute> or <xref:PostSharp.Patterns.Threading.ReaderWriterSynchronizedAttribute> threading model, and the method acquires the lock of the object. For a reader/writer synchronized class, this means a method with a <xref:PostSharp.Patterns.Threading.ReaderAttribute>, <xref:PostSharp.Patterns.Threading.WriterAttribute> or <xref:PostSharp.Patterns.Threading.UpgradeableReaderAttribute> attribute; without one, PostSharp reports <xref:thr016?text=THR016> instead;
* the class has the <xref:PostSharp.Patterns.Threading.ActorAttribute> threading model, and the method is dispatched to the actor;
* the method has the <xref:PostSharp.Patterns.Threading.DispatchedAttribute> aspect and its class has a threading model. `<ThreadingModel>` is then always `Actor`, whatever the threading model of the class.

`<ThreadingModel>` is the name of the threading model, for example `Synchronized`.

## Resolution

* Apply the <xref:PostSharp.Patterns.Threading.ReentrantAttribute> custom attribute to the method. Check that the method does not rely on the state of the object staying unchanged across an `await`: read the fields again after it.
* When the method does not need exclusive access to the object, apply the <xref:PostSharp.Patterns.Threading.ExplicitlySynchronizedAttribute> custom attribute to it instead.
