# CAC005: Parameter Types of the Invalidating and Cached Methods Are Incompatible

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Caching |
| **Message** | `The [InvalidateCache] aspect applied to <InvalidatingMethod> cannot invalidate <CachedMethod>: the type of the '<Parameter>' parameter of the cached method is not compatible with the type of the '<Parameter>' parameter in the invalidating method.` |

## Cause

To remove a value from the cache, the <xref:PostSharp.Patterns.Caching.InvalidateCacheAttribute> aspect rebuilds the cache key of the cached method, `<CachedMethod>`, by passing the arguments of the invalidating method, `<InvalidatingMethod>`, to the parameters of the same name. Each argument must therefore be a valid value of the parameter of the cached method: the type of the parameter of the invalidating method must be the same type, or a type derived from it or implementing it. PostSharp reports CAC005, on `<InvalidatingMethod>`, when this is not the case for the parameter named `<Parameter>`.

The check uses the rules of type assignment, not the conversions of C#: an `int` parameter does not match a `long` parameter, although C# converts an `int` to a `long` implicitly.

## Resolution

* Change the type of the parameter of the invalidating method to the type of the parameter of the cached method, or to a type derived from it.
* If the parameter of the cached method does not affect its value, exclude it from the cache key with the <xref:PostSharp.Patterns.Caching.NotCacheKeyAttribute> attribute.
