# LA0167: Aspect Applied to an Unsupported Kind of Declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot apply the aspect "<Aspect>" to "<Target>": aspects cannot be applied to a declaration of kind "<DeclarationKind>". Apply the aspect to a declaration of the source code instead. Code that selects the targets of an aspect, such as an IAspectProvider, can skip these declarations by checking MemberInfo.GetSemanticInfo().IsSelectable.` |

## Cause

The C# compiler implements some constructs of the source code with members that it generates: local functions and anonymous methods become methods with generated names, and async methods and iterators become state-machine types. PostSharp does not apply aspects to these declarations, whose <xref:PostSharp.Reflection.SemanticInfo.IsSelectable> property is `false`. `<DeclarationKind>` names the kind of the declaration, for example `local function`, `anonymous method` or `compiler-generated method`.

PostSharp reports LA0167 when an aspect reaches such a declaration:

* A custom attribute of an aspect is applied to a local function, which C# allows since version 9.
* An <xref:PostSharp.Aspects.IAspectProvider> provides an aspect for a member that it found by reflection, such as a method of a closure class or the `MoveNext` method of a state machine.
* A location-level aspect is applied to a parameter of a method that cannot receive aspects.

## Resolution

* Turn the local function or the anonymous method into a method of the class, and apply the aspect to this method.
* Apply the aspect to the method that contains the local function, if the aspect is meant for it.
* In an aspect provider, skip the members whose <xref:PostSharp.Reflection.ReflectionHelper.GetSemanticInfo*> returns a <xref:PostSharp.Reflection.SemanticInfo> whose <xref:PostSharp.Reflection.SemanticInfo.IsSelectable> property is `false`.
