# PS0111: Aspect Dependencies Form a Cycle

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Conflicting aspects on "<Declaration>": dependencies between transformations form a cycle. Members of this cycle are: <CycleMembers> Details of dependencies: <Details>` |

## Cause

When several aspects apply to the same declaration, PostSharp orders their transformations according to the dependencies of the aspect classes: <xref:PostSharp.Aspects.Dependencies.AspectTypeDependencyAttribute>, <xref:PostSharp.Aspects.Dependencies.AspectRoleDependencyAttribute> and <xref:PostSharp.Aspects.Dependencies.AspectEffectDependencyAttribute> with the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAction.Order> or <xref:PostSharp.Aspects.Dependencies.AspectDependencyAction.Require> action and a position, and the <xref:PostSharp.Aspects.Aspect.AspectPriority> of the aspects. PostSharp reports PS0111 when these dependencies form a cycle: each transformation of the cycle must come before the next one, and the last one before the first one, so no order satisfies them.

`<CycleMembers>` lists the transformations of the cycle, one per line. `<Details>` lists, for each of them, its dependencies and the roles that it provides. The message is therefore written on several lines.

## Resolution

Find in `<Details>` the dependency that contradicts the order you want, and change or remove it:

* When the aspect classes are yours, reverse the position of the wrong dependency, or remove it when another dependency already orders the aspects.
* When one aspect comes from a third party, you cannot change its dependencies, but you can change those of your own aspects, or add a dependency at assembly level with the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAttribute.TargetType> property.
