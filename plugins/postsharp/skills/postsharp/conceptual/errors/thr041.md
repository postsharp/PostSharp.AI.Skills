# THR041: Access Level Attribute in a Class Without a Threading Model

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Attribute [<Attribute>] cannot be applied to "<Method>" because no threading model has been applied to the class "<Class>"; it will be ignored.` |

## Cause

The access level attributes, <xref:PostSharp.Patterns.Threading.ReaderAttribute>, <xref:PostSharp.Patterns.Threading.WriterAttribute>, <xref:PostSharp.Patterns.Threading.UpgradeableReaderAttribute> and <xref:PostSharp.Patterns.Threading.YielderAttribute>, do not add any code by themselves. The threading model of the class, for example <xref:PostSharp.Patterns.Threading.ReaderWriterSynchronizedAttribute>, reads them and acquires the lock that they specify when the method is called.

After PostSharp has discovered the aspects of the project, it reports THR041 for each method with an access level attribute whose declaring class has no threading model. The method then runs without any lock, which usually means that the threading model was forgotten. `<Attribute>` is the full name of the attribute type, for example `PostSharp.Patterns.Threading.ReaderAttribute`.

## Resolution

* When the instances of the class are shared between threads, apply a threading model to the class, typically <xref:PostSharp.Patterns.Threading.ReaderWriterSynchronizedAttribute>.
* Otherwise, remove the access level attribute from the method.
