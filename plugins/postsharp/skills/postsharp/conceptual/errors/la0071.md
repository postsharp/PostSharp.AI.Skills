# LA0071: Introduced Method Does Not Match the Virtuality of the Existing Method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot introduce method "<Method>" into type "<TargetType>" because it is already defined in type "<DeclaringType>", and the IsVirtual property of the introduction does not match whether this method is virtual.` |

## Cause

When an aspect introduces a method with <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute> and sets its <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.OverrideAction> to <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrFail> or <xref:PostSharp.Aspects.Advices.MemberOverrideAction.OverrideOrIgnore>, and the target type itself already defines this method, PostSharp replaces the body of the existing method instead of adding a new one. The existing method keeps its modifiers, so it cannot become virtual or stop being virtual.

When you set the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.IsVirtual> property of the introduction explicitly, PostSharp compares it with the existing method, which counts as virtual when it is `virtual` and not `sealed`. When they differ, PostSharp reports LA0071. When you do not set <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.IsVirtual>, the existing method keeps its virtuality and PostSharp reports nothing.

The message concerns only a method of the target type, so `<DeclaringType>` is always `<TargetType>`. For a property or an event, PostSharp checks each accessor, so `<Method>` is the name of the accessor, such as `get_Name`.

## Resolution

* Give the existing method the virtuality that the introduction requires: add or remove the `virtual` modifier, or remove the `sealed` modifier.
* Remove the <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute.IsVirtual> property from the introduction, so that the existing method keeps its own virtuality.
