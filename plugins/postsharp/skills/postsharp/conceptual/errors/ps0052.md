# PS0052: Plug-In Required by a Library Not Found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The plug-in "<PlugIn>" required by "<Declaration>" was not found.` |

## Cause

A library can require that the projects that use it are processed by PostSharp, and by a given plug-in of PostSharp, with <xref:PostSharp.Extensibility.RequirePostSharpAttribute>. This custom attribute is applied to an attribute class, or to another declaration, of the library: when a project uses this attribute, PostSharp loads the plug-in that <xref:PostSharp.Extensibility.RequirePostSharpAttribute.PlugIn> names and adds the task that <xref:PostSharp.Extensibility.RequirePostSharpAttribute.Task> names. The pattern libraries of PostSharp use this mechanism to add their weavers.

PostSharp reports PS0052, and stops building the project, when it cannot find the plug-in `<PlugIn>` in its search path. `<Declaration>` is the declaration of the referenced library that carries the <xref:PostSharp.Extensibility.RequirePostSharpAttribute>. The usual causes are:

* The plug-in comes with a NuGet package that the project does not reference, for example because the project references the library, but not the package that contains its weaver.
* The packages of the library and of its plug-in have different versions.
* The name of the plug-in is misspelled in the <xref:PostSharp.Extensibility.RequirePostSharpAttribute>.

PostSharp does not report the message for the declarations of the project itself, only for those of the libraries that it references.

## Resolution

* Add to the project the NuGet package that contains the plug-in, with the same version as the package of the library. The documentation of the library names this package.
* When the plug-in is in a directory of your source tree, add this directory to the search path of PostSharp with the `PostSharpSearchPath` MSBuild property, or with a `SearchPath` element in `postsharp.config`. See <xref:msbuild-properties> and <xref:configuration-schema>.
* When you develop the library, give the name of the plug-in assembly without its extension. When the task is a task of PostSharp itself, such as the task of the aspect weaver, pass `null` as the name of the plug-in.
