# XAM079: Invalid Signature of the CanExecute Property of a Command

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Xaml |
| **Message** | `Error in the [Command] aspect applied to property <CommandProperty>: the signature of property <CanExecuteProperty> is incorrect. The CanExecute property must be a non-static and non-private property of type bool with a getter, for example "bool MyCanExecute { get; }" or "bool MyCanExecute { get; set; }".` |

## Cause

The <xref:PostSharp.Patterns.Xaml.CommandAttribute> aspect can implement the <xref:System.Windows.Input.ICommand.CanExecute(System.Object)> method of the command by reading a property of the view model. It looks for a property named `CanExecute<Name>` or `Can<Name>`, where `<Name>` is the name of the command property without the `Command` suffix, or for the property named by the <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteProperty> property of the aspect. A `CanExecute` method with one of these names takes precedence over the property, unless <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteProperty> is set.

The aspect reports XAM079 when this property cannot implement `CanExecute`, because:

* its type is not `bool`;
* it has no getter;
* its getter is static;
* its getter is private. Public, protected and internal getters are accepted.

PostSharp reports the message on the command property, not on the `CanExecute` property. In the current version, `<CanExecuteProperty>` shows the name of an internal type of the aspect instead of the name of the property.

Make the `CanExecute` property an instance property of type `bool` with a getter that is not private. If the property is not meant to implement `CanExecute`, rename it, or set <xref:PostSharp.Patterns.Xaml.CommandAttribute.CanExecuteProperty> to the name of another property.
