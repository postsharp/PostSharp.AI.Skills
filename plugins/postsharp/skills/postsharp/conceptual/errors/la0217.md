# LA0217: Advice Parameter Type Incompatible with the Target

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The parameter "<Parameter>" of the advice "<Advice>" is of type "<ParameterType>", which is not compatible with the value of type "<ValueType>" bound on "<Target>".` |

## Cause

Some bindings give a value whose type depends on the target of the advice: <xref:PostSharp.Aspects.Advices.ArgumentAttribute> gives an argument, <xref:PostSharp.Aspects.Advices.ReturnValueAttribute> the return value, <xref:PostSharp.Aspects.Advices.ThisAttribute> the instance, <xref:PostSharp.Aspects.Advices.LocationValueAttribute> the value of a field or property, and <xref:PostSharp.Aspects.Advices.DeclarationAttribute> a reflection object that is a method or a constructor. PostSharp checks the type of the parameter for each target, and reports LA0217 on the target when the parameter cannot receive the value:

* A parameter passed by value must generally be of the type of the value, or of a base type when the value is of a reference type. A parameter of a reference type, such as <xref:System.Object>, also receives a boxed copy of a value of a value type.
* A parameter passed as `in`, `ref` or `out` must be exactly of the type of the value.
* A `[Declaration]` parameter of type <xref:System.Reflection.MethodInfo> cannot receive a constructor, and a parameter of type <xref:System.Reflection.ConstructorInfo> cannot receive a method.

The message is reported on `<Target>`, the declaration to which the advice is applied. The same advice can fit some targets and not others.

## Resolution

Choose one of the following solutions:

* Give the parameter a type that receives the value on every target: a common base type, or <xref:System.Object>, which receives a boxed copy of a value type.
* Make the advice generic, so that PostSharp infers the type of the parameter for each target without boxing. See [Generic advice methods](xref:advice-parameter-binding#generic-advice-methods).
* Do not apply the aspect to the targets that do not fit. In a type-level aspect, the <xref:PostSharp.Aspects.Advices.MatchPointcut> pointcut skips these targets instead of reporting an error.
