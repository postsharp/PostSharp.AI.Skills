# PS0114: Aspects Not Ordered on the Same Declaration

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `Conflicting aspects on "<Declaration>": transformations "<Transformation1>" and "<Transformation2>" are not commutative, but they are not strongly ordered. Their order of execution is nondeterministic.` |

## Cause

When several aspects apply to the same declaration, PostSharp orders their transformations according to the aspect dependencies and the <xref:PostSharp.Aspects.Aspect.AspectPriority> of the aspects. Two transformations commute when their order does not change the behavior, for example when a dependency with the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAction.Commute> action says so. PostSharp reports PS0114 when two transformations do not commute and nothing orders them: the order that PostSharp chooses may change when you add, remove or rename an aspect, and the behavior of the program with it.

PostSharp follows the warning with an informational message that lists the dependencies of each transformation on the declaration.

## Resolution

Decide the order of the two aspects:

* When the aspect classes are yours, add a dependency to one of them: an <xref:PostSharp.Aspects.Dependencies.AspectTypeDependencyAttribute> with the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAction.Order> action, or an <xref:PostSharp.Aspects.Dependencies.AspectRoleDependencyAttribute> with a role that the other aspect provides with <xref:PostSharp.Aspects.Dependencies.ProvideAspectRoleAttribute>.
* When you only use the aspects, set the <xref:PostSharp.Aspects.Aspect.AspectPriority> property of both aspects where you apply them.
* When the order does not matter, add a dependency with the <xref:PostSharp.Aspects.Dependencies.AspectDependencyAction.Commute> action.
