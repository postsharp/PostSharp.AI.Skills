# PS0087: Post.Cast Between Incompatible Types

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot perform a post-compilation static cast from type <SourceType> to type <TargetType>: cannot assign <SourceType> to <TargetType>.` |

## Cause

An interface that an aspect introduces into a class is not visible to the C# compiler, so the source code cannot convert an instance of the class to this interface with a normal cast. The <xref:PostSharp.Post.Cast``2(``0)> method fills this gap: the C# compiler accepts any pair of reference types, and PostSharp checks the conversion at build time, after the aspects have been applied, and then removes the call.

PostSharp reports PS0087 when `<SourceType>`, the first type argument of the call, cannot be assigned to `<TargetType>`, the second type argument, in the woven assembly. The usual cause is that no aspect introduces `<TargetType>` into `<SourceType>`: the aspect is not applied to this class, or it introduces another interface. The message is reported on the line of the call.

## Resolution

* Apply the aspect that introduces `<TargetType>` to `<SourceType>`, directly or by multicasting.
* When the aspect is applied, check that it introduces `<TargetType>` and not another interface, for example with <xref:PostSharp.Aspects.Advices.IntroduceInterfaceAttribute>.
* When the conversion is not meant to depend on an aspect, use a normal cast instead of <xref:PostSharp.Post.Cast``2(``0)>.
