# LA0082: Imported Event Not Found in the Target Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot bind field "<Field>" to type "<TargetType>": cannot find an event named <EventNames> in type "<TargetType>" or its ancestors.` |

## Cause

An aspect imports an event of its target class with a field of type <xref:PostSharp.Aspects.Advices.Event`1> annotated with <xref:PostSharp.Aspects.Advices.ImportMemberAttribute>. PostSharp looks for an event with the name given to the attribute in the target type and in its base types. When the <xref:PostSharp.Aspects.Advices.ImportMemberAttribute.IsRequired> property is `true`, PostSharp reports LA0082 for each target type where it finds no such event. When <xref:PostSharp.Aspects.Advices.ImportMemberAttribute.IsRequired> is `false`, which is the default, the field stays `null` instead.

The event is not found when no event has this name, for example because of a typo, or when the event is a `private` event of a base class.

`<EventNames>` lists the names given to the attribute, each in quotes. PostSharp reports the error on the target type, not on the field of the aspect. When the event exists but its delegate type differs from the type argument of the field, PostSharp reports <xref:la0083?text=LA0083> instead.

## Resolution

* Correct the name given to <xref:PostSharp.Aspects.Advices.ImportMemberAttribute>, or pass several names when the event can have one of several names.
* Make the event of the base class accessible to the target class, for example `protected` instead of `private`.
* When the aspect can work without the event, set <xref:PostSharp.Aspects.Advices.ImportMemberAttribute.IsRequired> to `false` and check that the field is not `null` before using it.
