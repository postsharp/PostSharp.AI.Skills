# LA0132: Two Advice Methods of the Same Name in an Aspect Hierarchy

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `An aspect class and its base class cannot both define an advice method named "<Name>": it is defined in "<BaseType>" and in "<DerivedType>". Rename one of the advice methods.` |

## Cause

PostSharp collects the advices of an aspect from the aspect class and from all its base classes, and it identifies advice methods by their name, for example in <xref:PostSharp.Aspects.Dependencies.AdviceDependencyAttribute>, which orders an advice with respect to another one designated by the name of its method. Therefore, the advice methods declared in different classes of the hierarchy must have different names. Overloads declared in the same class are not affected.

PostSharp reads the advices of the aspect class first, then those of its base classes, so it reports LA0132 on the advice method of the base class, `<BaseType>`, and ignores this advice. `<DerivedType>` is the class that declares the first advice method of this name. The message is typical of an advice method that hides the advice method of its base class with the `new` modifier.

## Resolution

Rename one of the advice methods, so that each advice method of the aspect hierarchy has a name of its own. To change the behavior of an advice in a derived aspect class, make the advice call a virtual method and override that method instead.
