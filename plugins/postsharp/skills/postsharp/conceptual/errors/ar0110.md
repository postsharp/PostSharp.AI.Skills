# AR0110: Type Name Does Not Match the Naming Convention

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `The name of type <Type> does not match the "<Pattern>" pattern of the [NamingConvention] constraint applied to this type or to one of its base classes or interfaces.` |

## Cause

The <xref:PostSharp.Constraints.NamingConventionAttribute> constraint, applied to a class or an interface, enforces a naming convention: the name of this type, and the names of the classes derived from it or implementing it, must match a pattern. A pattern that contains `*` is a wildcard pattern, which must match the whole name; a pattern that starts with `regex:` is a regular expression, which only needs to match a part of the name.

PostSharp reports AR0110 on each type whose name does not match the pattern. It checks the short name of the type, without its namespace or the names of the types that contain it.

AR0110 is a warning by default. Its severity comes from the <xref:PostSharp.Constraints.NamingConventionAttribute.Severity> property of the constraint, which you can set to <xref:PostSharp.Extensibility.SeverityType.Error>.

## Resolution

* Rename the type so that its name matches the pattern.
* When the convention is too strict, change the pattern of the constraint. For example, a regular expression such as `regex:(Repository|Store)$` accepts two suffixes.
