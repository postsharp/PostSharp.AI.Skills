# LA0035: Non-Serialized Aspect Provided as an Instance

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `The aspect <Aspect> has no serializer, but it has been provided to <Target> as an instance. An aspect that is not serialized must be provided as an ObjectConstruction.` |

## Cause

PostSharp creates aspects at build time and must recreate them at run time. By default, it serializes the build-time instance and deserializes it at run time. An aspect whose serializer is <xref:PostSharp.Aspects.Serialization.MsilAspectSerializer> is not serialized: PostSharp emits code that calls its constructor and sets its fields and properties, from the custom attribute or the <xref:PostSharp.Reflection.ObjectConstruction> that describes it.

An aspect that implements <xref:PostSharp.Aspects.IAspectProvider> can provide another aspect in two ways: as an instance, with the constructor of <xref:PostSharp.Aspects.AspectInstance> that takes an <xref:PostSharp.Aspects.IAspect>, or as a construction, with the constructor that takes an <xref:PostSharp.Reflection.ObjectConstruction>. An instance carries no description of how to construct it, so PostSharp can only serialize it. When the provided aspect is not serialized and is provided as an instance, PostSharp reports LA0035 on the aspect class.

## Resolution

Choose one of these fixes:

* Provide the aspect as an <xref:PostSharp.Reflection.ObjectConstruction>, which names the aspect type and the arguments of its constructor, and sets its properties with <xref:PostSharp.Reflection.ObjectConstruction.NamedArguments>.
* Make the aspect serializable instead: remove the <xref:PostSharp.Aspects.Serialization.MsilAspectSerializer> configuration and add the [<xref:PostSharp.Serialization.PSerializableAttribute>] attribute to the aspect class.
