# LA0088: Advice Requires a Target Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot use the advice "<Advice>" in an aspect applied to <DeclarationKind> "<Declaration>" because this advice requires a target type. Use a type-level aspect instead, which you can multicast from the assembly to types.` |

## Cause

Some advices transform the type that the aspect is applied to, or the declaring type of the member that it is applied to: <xref:PostSharp.Aspects.Advices.IntroduceMemberAttribute>, <xref:PostSharp.Aspects.Advices.IntroduceInterfaceAttribute>, <xref:PostSharp.Aspects.Advices.ImportMemberAttribute>, <xref:PostSharp.Aspects.Advices.InitializeAspectInstanceAdvice>, <xref:PostSharp.Aspects.Advices.OnAspectsInitializedAdvice> and <xref:PostSharp.Aspects.Advices.OnInstanceConstructedAdvice>. An aspect applied to the assembly itself, such as an <xref:PostSharp.Aspects.AssemblyLevelAspect>, has no such type, so PostSharp reports LA0088 for each of these advices.

`<Advice>` is the kind of advice, such as `OnInstanceConstructed`, not the name of the advice method. `<DeclarationKind>` and `<Declaration>` are the kind and the name of the target of the aspect, such as `Assembly` and the name of the assembly. The message has no location in the source code.

## Resolution

Derive the aspect from a type-level aspect, such as <xref:PostSharp.Aspects.InstanceLevelAspect> or <xref:PostSharp.Aspects.TypeLevelAspect>, and apply it to the types that it must transform. To keep the custom attribute on the assembly, select the types with the <xref:PostSharp.Extensibility.MulticastAttribute.AttributeTargetTypes> property: PostSharp multicasts the aspect from the assembly to each of these types.
