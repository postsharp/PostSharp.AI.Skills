# PS0010: Plug-In or Configuration File Not Found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Cannot find the plug-in assembly or configuration file "<FileName>".` |

## Cause

A `Using` element of a configuration file, such as `postsharp.config`, imports another configuration file or a plug-in into the project. See <xref:configuration-schema>. PostSharp reports PS0010, and stops building the project, when it cannot find the file that the `File` attribute names:

* When the name has no path, PostSharp searches the file in the directories of its search path, which include the plug-in directories, the directories of the references of the project, and the directories of the `SearchPath` elements and of the `PostSharpSearchPath` MSBuild property. `<FileName>` is the name as the `File` attribute gives it.
* When the name has a relative or an absolute path, PostSharp looks only at this path, relative to the directory of the configuration file, and `<FileName>` is the full path that it tried.

PostSharp also reports PS0010 when a plug-in or a configuration file that the build passes to PostSharp does not exist.

## Resolution

* Check the spelling of the file name, and that the file is where the full path in the message says.
* To import a configuration file of your source tree, give its path relative to the configuration file that contains the `Using` element, for example `.\LoggingProfiles.config` or `..\Shared\LoggingProfiles.config`, so that PostSharp does not depend on the search path to find it.
* To import a plug-in by its name, add its directory to the search path with a `SearchPath` element or with the `PostSharpSearchPath` MSBuild property. See <xref:msbuild-properties>.
* When the file was removed on purpose, remove the `Using` element, or give it a `Condition`.
