# LA0110: Instance-Scoped Aspect Selects a Member of Another Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Error while evaluating the MethodPointcut "<PointcutMethod>" on "<AspectTarget>": cannot select the <ElementKind> "<Element>" because it does not belong to type "<TargetType>", and an instance-scoped aspect can only add advices to the members of its own target type.` |

## Cause

An advice can select its targets with <xref:PostSharp.Aspects.Advices.MethodPointcut>, which names a method of the aspect that returns the declarations to enhance. An instance-scoped aspect, such as an <xref:PostSharp.Aspects.InstanceLevelAspect>, has one instance per instance of its target type, stored in a field of that type. Its advices can only run in the members of that type, which can read the field: a member of another type, even of a base class, cannot reach the instance of the aspect.

PostSharp reports LA0110 for each element that the pointcut method returns when the element is declared in another type than `<TargetType>`, the type that the aspect is applied to. The error is reported on the pointcut method, and the element is skipped. `<ElementKind>` is the kind of metadata element, such as `MethodDef` for a method.

Static-scoped aspects, such as <xref:PostSharp.Aspects.TypeLevelAspect>, do not have this restriction.

## Resolution

* Select only the members that the target type declares, with `BindingFlags.DeclaredOnly`, and apply the aspect to the other types whose members you want to enhance.
* If the aspect does not need an instance per instance of the target type, derive it from <xref:PostSharp.Aspects.TypeLevelAspect> instead.
