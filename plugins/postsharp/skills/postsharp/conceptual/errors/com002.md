# COM002: Field or Property Has No Relationship Attribute

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Common |
| **Message** | `Field/property <DeclaringType>.<Member> must be annotated with a custom attribute [Child], [Reference] or [Parent].` |

## Cause

The <xref:PostSharp.Patterns.Model.AggregatableAttribute> aspect must know, for each field and automatic property of the class, whether the object it holds is a child of the instance, a reference to another object, or the parent of the instance. PostSharp cannot guess it from the type: an object of a class can be owned by the instance as well as shared with other objects.

PostSharp therefore reports COM002 for each field or automatic property whose type can be a child, typically a class, an interface or a collection, when the member has no <xref:PostSharp.Patterns.Model.ChildAttribute>, <xref:PostSharp.Patterns.Model.ReferenceAttribute> or <xref:PostSharp.Patterns.Model.ParentAttribute> attribute and no rule of rule-based annotation gives its relationship. Fields and properties of a type that cannot be a child, such as a string or a value type, need no attribute.

## Resolution

Add the attribute that describes the relationship:

* <xref:PostSharp.Patterns.Model.ChildAttribute> when the instance owns the object, which then gets the instance as its parent.
* <xref:PostSharp.Patterns.Model.ReferenceAttribute> when the object belongs to another part of the graph or is shared.
* <xref:PostSharp.Patterns.Model.ParentAttribute> when the field or property receives the parent of the instance.

When many fields follow the same convention, you can give their relationship with a rule instead of an attribute on each of them, as described in <xref:aggregatable-adding-programmatically>.
