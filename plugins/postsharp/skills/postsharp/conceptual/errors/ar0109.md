# AR0109: Invalid Naming Convention Pattern

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Error in the [NamingConvention] constraint applied to <Type>: the string "<Pattern>" is not a valid pattern. It should contain a "*" or start with the "regex:" prefix.` |

## Cause

The <xref:PostSharp.Constraints.NamingConventionAttribute> constraint, applied to a class or an interface, checks that the names of this type and of the types derived from it match a pattern. The pattern is one of:

* a wildcard pattern, which contains at least one `*`, such as `*Repository`;
* a regular expression, with the `regex:` prefix, such as `regex:^I[A-Z]`.

PostSharp reports AR0109 when the pattern is empty, or is a plain name without a `*` and without the `regex:` prefix. PostSharp then does not check the names.

The constraint is inherited by the derived classes and by the classes that implement the interface, so PostSharp reports AR0109 once for the type that has the attribute and once for each of these types, at the location of the type rather than of the attribute. `<Type>` is the type being checked.

## Resolution

Correct the pattern:

* Add a `*` wherever the name can contain any text. `*Repository` matches every name that ends with `Repository`, including `Repository` itself.
* To write a regular expression, start the pattern with `regex:`. The regular expression is not anchored: add `^` and `$` to match the whole name.
