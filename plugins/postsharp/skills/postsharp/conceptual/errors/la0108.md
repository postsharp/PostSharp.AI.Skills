# LA0108: Advice Passes Its Arguments to a Method That PostSharp Cannot Analyze

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | PostSharp |
| **Message** | `For better runtime performance, avoid a virtual call or a call to another assembly from the advice "<Advice>" to the method "<Method>": PostSharp cannot analyze this method, so it disables the optimizations of the advice. Make the method non-virtual, or do not pass it a parameter of type "<AdviceArgsType>".` |

## Cause

At build time, PostSharp analyzes the body of each advice, such as <xref:PostSharp.Aspects.OnMethodBoundaryAspect.OnEntry*>, to find which properties of its <xref:PostSharp.Aspects.AdviceArgs> parameter it uses. It then generates code that initializes only these properties, which makes the aspect faster at run time. When the advice passes its arguments to another method of the same assembly, PostSharp analyzes that method too.

PostSharp cannot analyze the called method, and reports LA0108, when the advice passes its arguments to:

* a virtual method that is not sealed, in a class that is not sealed, because a derived class can override it with code that uses other properties;
* an instance method of another assembly;
* a delegate created from a virtual method.

PostSharp then disables all the optimizations of the advice. The aspect still works, so this is a warning, but the code generated for each target method initializes every property of the arguments.

`<AdviceArgsType>` is always <xref:PostSharp.Aspects.AdviceArgs>, the base class of all advice arguments, such as <xref:PostSharp.Aspects.MethodExecutionArgs>.

## Resolution

* Make the called method non-virtual, for example `private`, or seal it.
* When the method is in another assembly, or must stay virtual, read the properties that it needs in the advice and pass their values instead of the advice arguments.
