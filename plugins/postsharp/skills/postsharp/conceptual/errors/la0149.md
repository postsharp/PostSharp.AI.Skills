# LA0149: Aspect Serialized with BinaryFormatter Has a Delegate Field

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | ``Cannot serialize the delegate type "<DelegateType>": fields of a delegate type in an aspect class must be marked as [NonSerialized].`` |

## Cause

PostSharp serializes the aspect instances at build time and deserializes them at run time. An aspect marked as [<xref:System.SerializableAttribute>] instead of [<xref:PostSharp.Serialization.PSerializableAttribute>] is serialized with `BinaryFormatter`, which is allowed only when the `PostSharpBinaryFormatterAllowed` MSBuild property is `True` (otherwise PostSharp reports <xref:la0206?text=LA0206>). A delegate refers to a method and often to a closure, which cannot be restored reliably in another process, so PostSharp refuses to serialize it.

PostSharp reports LA0149 when a field of a delegate type holds a delegate at the end of the build-time initialization of the aspect, for example because the constructor or `CompileTimeInitialize` assigns it. A field that is `null` at this time does not cause the message. `<DelegateType>` is the type of the delegate, such as ``System.Func`2<System.String,System.String>``. The message has no location: look for the delegate fields of the `[Serializable]` aspects of the project.

## Resolution

Exclude the field from serialization and create the delegate at run time:

* Mark the field as [<xref:System.NonSerializedAttribute>], and assign it in `RuntimeInitialize`, which PostSharp calls at run time after deserializing the aspect.
* Better, serialize the aspect with the portable serializer: replace [<xref:System.SerializableAttribute>] with [<xref:PostSharp.Serialization.PSerializableAttribute>], and mark the field as [<xref:PostSharp.Serialization.PNonSerializedAttribute>]. `BinaryFormatter` is obsolete and is not available at run time on recent versions of .NET.
