# THR039: Async Method of an Actor Has an Unsupported Return Type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp.Patterns.Threading |
| **Message** | `Async method "<Method>" must have the return type void, Task or Task<T> because its declaring class has the [Actor] threading model and the method is an entry point of the actor, such as a public or internal method. Async methods with other return types, such as ValueTask<T>, are not supported.` |

## Cause

The <xref:PostSharp.Patterns.Threading.ActorAttribute> threading model dispatches every call to an entry point of the actor to the queue of the actor, so that the actor processes one call at a time. The entry points are the public, internal and protected internal methods, the implementations of interface methods, and the methods annotated with <xref:PostSharp.Patterns.Threading.EntryPointAttribute>.

The actor can only dispatch an `async` method that returns `void`, `Task` or `Task<T>`. PostSharp reports THR039 when an `async` entry point returns another awaitable type, for example `ValueTask` or `ValueTask<T>`.

In the following example, the `GetPriceAsync` method returns a `ValueTask<int>`. The method is annotated with <xref:PostSharp.Patterns.Threading.ReentrantAttribute> because the actor requires it on every `async` method, which PostSharp otherwise reports with <xref:thr017?text=THR017>.

## Resolution

* Return a `Task` instead of a `ValueTask`, or a `Task<T>` instead of a `ValueTask<T>`. The callers that `await` the method do not change.
* When the method does not need to be called from outside the actor, make it private, so that it is not an entry point and the actor does not dispatch it.
