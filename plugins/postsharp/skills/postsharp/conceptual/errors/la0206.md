# LA0206: Aspect Class Uses Binary Serialization

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | PostSharp |
| **Message** | `Aspect "<AspectType>" is annotated with [Serializable]. Using [Serializable] on aspects is not supported because it requires BinaryFormatter at run time. BinaryFormatter is considered dangerous, and using it can cause an exception at run time depending on the run-time settings. Use [PSerializable] instead. If you are certain that you need [Serializable], set the PostSharpBinaryFormatterAllowed MSBuild property to True to suppress this message. See https://bit.ly/ps-binary-formatter for more information.` |

## Cause

PostSharp creates the aspect instances at build time and serializes them into the assembly. It chooses the serializer from the aspect class. When the aspect class has neither a serializer of its own nor the [<xref:PostSharp.Serialization.PSerializableAttribute>] attribute, but has the [<xref:System.SerializableAttribute>] attribute, the aspect would be deserialized at run time with <xref:System.Runtime.Serialization.Formatters.Binary.BinaryFormatter>. Microsoft considers `BinaryFormatter` insecure, and recent versions of .NET throw an exception when it is used, so PostSharp reports LA0206 on the aspect class `<AspectType>` unless the `PostSharpBinaryFormatterAllowed` MSBuild property is `True`.

## Resolution

* Replace [<xref:System.SerializableAttribute>] with [<xref:PostSharp.Serialization.PSerializableAttribute>] on the aspect class, and on the classes of its serialized fields. Replace [<xref:System.NonSerializedAttribute>] with [<xref:PostSharp.Serialization.PNonSerializedAttribute>].
* Only for a legacy application that cannot change its aspects, set the `PostSharpBinaryFormatterAllowed` MSBuild property to `True`. This is not recommended: see <xref:binary-formatter-security> for the steps that the run time then requires.
